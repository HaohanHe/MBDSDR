## 0. 先报：绘制耗时与图层矩阵

### 0.1 口径

- 固定 `QImage(1280×800, ARGB32_Premultiplied)`，`widget.render(img)` 计一次 `paintEvent` 全程；不含窗口合成/上屏。
- 每场景 7–9 次采样取中位数与最小值；**三轮独立进程**（正序 / 逆序 / 交叉），用于识别 CPU 降频污染。
- 噪声底：`off:eqgrid`、`off:night` 是**无操作对照**（默认态的 eqgrid/night 本就没开），它们与 `default` 的差值即噪声底，实测 −5.0 ~ −6.3 ms。因此**单层差值 < 2 ms 一律不作为事实**。
- 绝对耗时随机器负载漂移：本测量窗口内同时有构建与其他调研 agent 在跑，同一二进制同一场景从 16.2 ms 漂到 29.1 ms。

### 0.5 三条可执行结论

1. **赤道网格是唯一的功能性性能缺陷**：+30~49 ms，单层就吃掉 1.5–2.5 倍帧预算；改成一次 `j2000_to_altaz_many` 批量调用（仓库已有该函数）即可，无需算法重写。
2. **默认帧本身已贴着预算线**：恒星 + 星座 = 10.3–15.4 ms，占默认帧 **55–65%**，且占比与画布尺寸无关（见 §2.4），所以"换小窗"救不了，只能降对象数或降绘制工序。
3. 除 eqgrid 外，没有第二个 >5 ms 的可归因图层；`dso`/`azgrid`/`planets` 都在 1–3 ms，不是优先项。

## 3. 新缺口

> 每条格式：现象 / 影响 / 严重度 / 成本 / 是否需产品决定。

### G1 · DSO 用恒星裸眼极限做亮度门，117 条只剩 12 条

- `path:line`：`desktop/rf_sky_view.py:4674-4677`
- 现象：`star_draw(mag + extinction, self._bortle)` 返回 `r_star <= 0` 即 `continue`。这是按**点源裸眼极限**（6.5 等）判一个**有面积、可累积亮度**的延展天体。M33（5.7 等、面积 70′×40′）、M34/M35/M36/M37/M39、NGC 869/884 等一并被砍掉。
- 影响：暗空下星象仪"深空天体"层几乎空转；用户开 DSO 层看不到 DSO，会判定"没有数据"（与银河的诚实空态混为一谈）。Bortle 1 与 Bortle 3 完全相同（都 12 条），暗空无收益。
- 严重度：**P1**
- 成本：小（引入面亮度门或按类型给不同阈值，`dso.py` 已有 `size_arcmin` 字段；判定式单点）。
- 产品决定：**需要**——"DSO 层该按面亮度还是按星等"是取舍，且必须决定是否承认"面亮度模型缺失"（当前 `extinction_delta_mag` 只按点源消光）。

### G2 · 赤道网格单帧 +30~49 ms，直接击穿帧预算

- `path:line`：`desktop/rf_sky_view.py:5427-5462`（`_draw_eq_grid`，循环内标量转换在 `:5455`，循环内重复 import 在 `:5456`）
- 现象：354 次标量 `j2000_to_altaz`（每次 ~57 µs），循环内 20.19 ms，整层 34.0–52.1 ms（隔离），开该层全帧 50.0–75.6 ms。
- 影响：开赤道网格后帧间隔 50–76 ms ≈ 13–20 fps；拖拽/缩放明显粘手，而赤道网格正是"找深空目标"最常用的辅助层。
- 严重度：**P1**
- 成本：小（`j2000_to_altaz_many` 已存在于 `mbdsdr_ai/celestial_geometry.py`，一次批量；循环内 import 移出）。
- 产品决定：**不需要**（纯性能，行为不变）。

### G3 · 中文常用星名搜不到（北极星/北斗七星/天狼星/织女星/老人星全 0 命中）

- `path:line`：`desktop/rf_sky_view.py:3314-3369`（`_on_search_text`，星表匹配 + 54 颗亮星中文表兜底）
- 现象：星表 431 个专名**全英文**（`Polaris`/`Sirius`/`Vega`），中文只有 54 颗的别名表（`勾陈一`/`天狼`/`织女`）。实测：`北极星`、`北斗`、`北斗七星`、`天狼星`、`织女星`、`老人星` → **0 命中**；`勾陈一`、`天狼`、`织女` → 各 1 命中。单次搜索 0.02–0.22 ms，**无性能问题**。
- 影响：中文用户最自然的三个词（北极星、北斗七星、天狼星）全部落空，且"北斗七星"是**星座/星组**不是单星，即使补别名也命中不了。搜索框成了"必须知道学名才能用"。
- 严重度：**P1**
- 成本：小-中（补常用别名表 + 星组→多目标定位；`xingguan` 已有 1193 段可用于"北斗"这样的星官级定位）。
- 产品决定：**需要**——"搜到一组星时是逐个高亮还是整体缩放框住"，以及是否接受"别名表不是穷举"的诚实边界。

### G4 · Bortle 1 与 Bortle 3 星数完全相同（1695 = 1695）

- `path:line`：`mbdsdr_ai/skyengine/stars.py:155-171`
- 现象：`NAKED_EYE_LIMIT_SCALE=6.5` 且 `max(0, bortle-3)` 截断 → Bortle ≤3 恒为 6.5 等。实测 Bortle 1 与 3 都是 1695 颗、极限 6.5。
- 影响：用户把光害从 3 调到 1（真正的暗空）画面**一个星都不多**，光害设置在最该体现差别的区间失效；也与星表能力（mag ≤ 9.0）不匹配——暗空本可画到 7.5–8 等。
- 严重度：**P1**
- 成本：小（把截断改为 `SCALE + slope*(3-bortle)` 或在 Bortle≤3 段改用更细的表；`star_catalog` 与绘制层已共用同一函数，改一处即可）。
- 产品决定：**需要**——各 Bortle 档的极限星等取值是产品口径，需背书（尤其别与"实测天空亮度"打架）。

### G5 · 恒星 + 星座占默认帧 55–65%，且与分辨率无关

- `path:line`：`desktop/rf_sky_view.py:4432-4500`（`_draw_stars`）、`4922-4970`（`_draw_constellations`）
- 现象：默认帧 19.95–29.07 ms 中，stars 6.60–10.38 ms + constellations 3.67–4.99 ms。画布从 1920×1080 缩到 600×500（像素降 5.8 倍），全帧只从 21.4 降到 16.5 ms。
- 影响：性能天花板锁在对象数上；小窗口/低端机不会自动变流畅，而"多开一个窗口看星图"是常见用法。
- 严重度：**P2**
- 成本：中（恒星按 mag 分桶一次性 `drawPoints`、星座线合并为单 path；两者都是局部重写绘制段）。
- 产品决定：**不需要**（除非要牺牲星点辉光观感，那需要）。

### G7 · 小窗下状态卡固定 240×330，占 82% 高度

- 严重度：**P2**

- 产品决定：**需要**——小窗下优先保卡片信息还是保天空面积。

### G8 · 白天/暮光下星座线照画，但星已被整层隐藏

- 影响：Bortle 是"一眼看差异"的观感参数（且当前 Bortle 1=3，见 G4），藏在设置页让用户根本发现不了它影响星数。
- 严重度：**P2**
- 成本：小（图层弹层旁边加一个 1–9 选择器，与 schema 同源）。
- 产品决定：**不需要**。

### G12 · 行星在常用 FOV 不可分辨，且无一键放大

- `path:line`：`desktop/rf_sky_view.py:6164`（`_planet_screen_disc`）、`6218`（`_draw_planets`）
- 现象：FOV 120° 时土星圆面半径 0.02 px、天王星 0.0 px（实测）。要看到土星环需 FOV 收到角分级，但没有任何"对准并放大到该天体"的入口（`goto_animated` 只居中不改 FOV）。
- 影响：行星层在默认视野里等于"多两个点"；用户点开行星信息卡后无法继续"看它"，体验断在最有期待的一步。
- 严重度：**P2**
- 成本：小（goto 后按视直径自动设 FOV 或提供"放大到可分辨"按钮）。
- 产品决定：**需要**——放大到多少算"可分辨"，以及是否要在极窄 FOV 下开大气色散/相位提示。

### G13 · 无视图旋转入口（`rotation` 字段无人写）

- `path:line`：`mbdsdr_ai/sky_interaction.py:209`（`rotation: float = 0.0`）、`287`（`build_view_rotation`）
- 现象：`ViewState.rotation` 参与矩阵构建，但全仓无写入点、无快捷键、无按钮；拖拽只改 `pan`。
- 影响：低仰角看东/西天时无法把地平线摆正（手机横持/斜靠的常见姿势）；也无法做"以天极为上"的对照观察。
- 严重度：**P3**
- 成本：小（加 `rotate` 手势/快捷键 + 复位）。
- 产品决定：**需要**（是否允许任意旋转，会不会让"上=天顶"的默认心智失效）。

### G14 · 星座/星官名不可搜

- `path:line`：`desktop/rf_sky_view.py:3314-3369`（搜索只有恒星星表、亮星中文表、DSO 三个分支）
- 现象：无星座分支。搜"猎户""北斗""天琴"均落空（星座数据 `constellations` 842 段 / `xingguan` 1193 段都在内存里）。
- 影响：与 G3 叠加，中文用户的两条自然路径（星名、星座名）都断。
- 严重度：**P3**
- 成本：小（复用 `overlay_layers` 的 name 锚 + `goto` 到质心/包围盒）。
- 产品决定：**不需要**。

### G15 · 状态卡只能滚轮滚动，无滚动条/键盘

- `path:line`：`desktop/rf_sky_view.py:7731`（`_status_card_max_scroll`）、`7736`（`_scroll_status_card`），唯一调用点是滚轮（`:7765`）
- 现象：内容超长时只响应 `wheelEvent`；无可见滚动条、无 PageUp/PageDown、无拖拽。
- 影响：触屏（`PinchZoomMixin` 代表该产品关心触屏）与纯键盘用户无法翻到卡片下半部分；也没有"还有更多"的视觉暗示。
- 严重度：**P3**
- 成本：小（画一个细滚动条 + 键盘分支）。
- 产品决定：**不需要**。

### G16 · DSO 注释写"124 条"，实际目录 117 条

- `path:line`：`desktop/rf_sky_view.py:4632`（`# 不再逐条重建矩阵（124 条 × 3 个矩阵曾占单帧 ~11ms）`）
- 现象：`mbdsdr_ai/astronomy/dso.py:41` 的 `BUILTIN_CATALOG` 实测 117 条（Messier 1–110 + 7 个 NGC）。
- 影响：纯注释，但本仓把注释当证据用（`scripts/verify_claims.py` 口径），数字错的注释会被后续引用成"事实"。
- 严重度：**P3**
- 成本：极小。
- 产品决定：**不需要**。

### G17 · "909 星"这句结论不可复跑

- `path:line`：`desktop/rf_sky_view.py:5159`（`_stars_hidden_by_daylight`）/ `4432`（`_draw_stars`）——星数由 时刻 × 站址 × FOV × 视向 × Bortle × 消光 六元组决定，而这六元组未随结论记录。
- 现象：同一星表同一代码，本轮实测从 601（alt 15°）到 1695（天顶）都能出现；已知结论的 909 没有记录当时的口径。
- 影响：回归测试无法用它当基线；下次有人"复跑得到 1695"会误判为回退。
- 严重度：**P3**
- 成本：极小（把六元组写进结论/测试注释）。
- 产品决定：**不需要**。

## 6. 复现方法

```powershell
# 1) 导出 HEAD 快照（不要用 PowerShell > 重定向，会写 BOM/UTF-16）
cd D:\mbdsdr\MBDSDR
python -c "import subprocess,pathlib; pathlib.Path('D:/mbdsdr/output/tmp/snap/rf_sky_view_head.py').write_bytes(subprocess.check_output(['git','show','HEAD:desktop/rf_sky_view.py']))"

# 2) 以模块名 rf_sky_view 载入快照，构造 QApplication（必须在 windows 平台）
$env:QT_QPA_PLATFORM="windows"
$env:MBDSDR_OFFLINE="1"
python D:/mbdsdr/output/tmp/gap_sky_probe5.py   # 三轮矩阵 + 分层隔离
python D:/mbdsdr/output/tmp/gap_sky_probe3.py   # eqgrid 归因 / DSO 漏斗 / 搜索
python D:/mbdsdr/output/tmp/gap_sky_probe4.py   # 叠加层几何 / 中文别名 / 标签
```

探针要点（不落任何配置，不改产品代码）：
- `widget.setAttribute(Qt.WA_DontShowOnScreen, True)` 后 `widget.resize(1280, 800)`，再 `widget.render(QImage)`；`grab()` 会走不同的重绘路径，不用于比较。
- 计时用 `time.perf_counter()`，每场景 7–9 次取中位数；三轮独立进程交叉排序，并保留 `off:eqgrid`/`off:night` 作无操作对照来标定噪声底。
- 固定时刻 `2026-11-11 14:00 UTC`、站址 `40.0/116.0/50`；星数、DSO 漏斗、行星高度全部在同一 `TimeEngine` 状态下取。
