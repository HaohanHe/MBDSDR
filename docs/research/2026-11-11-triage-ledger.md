# 在途半成品判别器 · 只读试用台账（2026-11-11 起一周）

**性质**：只读、人工、不进 CI、不作门禁。判别器 `scripts/triage_failure.py` 恒以
退出码 0 结束，只打印结论行；本台账只记录**人**核对后的结论。

## 一、谁在什么时候跑

- **触发点**：每次 `scripts/run_all_tests.sh` 出现 FAIL 之后，由**当次改动者**立刻跑一次
  （同一台机器、同一工作区，越早越能对上「当时的工作区状态」）。
- **频率**：不设定时任务；没有失败就没有样本，空跑没有意义。
- **准入**：一周内只在本地跑，不改任何测试/CI 配置。一周后按「命中是否全为真在途、
  有无误报」决定是否接进 CI 失败摘要。

## 二、怎么跑

```bash
# 失败时 run_all_tests.sh 会打印一行 junitxml 绝对路径，直接喂给它：
python scripts/triage_failure.py --junitxml scratch/test-logs/pytest_tests_g0.xml
```

输出三态：`疑似在途半成品` / `不确定` / **不发声**（符号在 HEAD 里存在 = 真缺陷，交给人看）。

## 三、记什么

每跑一次，向 §四 追加一行；「人工核对结论」必须落到下面四类之一，不许写「待定」：

| 结论 | 含义 | 后续动作 |
|---|---|---|
| `真在途` | 符号只存在于工作区未提交改动 | 记下写盘线，等其收尾后复跑；不报产品红 |
| `真缺陷` | 符号在 HEAD 存在，判别器不发声，红是真的 | 按正常流程修 |
| `窗口已关闭` | 跑的时候符号已写进工作区，异常来自更早的中间态 | 复跑确认绿即可，不追 |
| `误报` | 判别器判了「在途」但实际是产品缺陷 | **必须记**，这是评估是否接 CI 的唯一依据 |

### 「误报」必须带原因

只写「误报」两个字等于没记。每条 `误报` 在「人工核对结论」列写成
`误报（原因：<码>）`，`<码>` 只能是下列之一，另加一句人话说明：

| 原因码 | 为什么算误报 |
|---|---|
| `符号提取失败` | 异常文本里取不到符号（如 `AttributeError: object has no attribute`），判别器本应降级「不确定」却判了在途 |
| `窗口已关闭` | 跑的时候符号已写进工作区，异常来自更早的中间态；判别器没识别出窗口已关 |
| `日志过期` | 用的是上一轮/别的会话的 junitxml，与当前工作区状态对不上 |
| `接口漂移` | 符号在 HEAD 无定义、工作区也干净，是已提交代码的契约变化，不是在途半成品 |
| `动态注入` | 符号经 `__getattr__`/`setattr` 提供，本就不该静态存在 |

## 五、一周汇总模板（带分母）

只填 §四 之后，把下面的表照着抄一遍填数——**没有分母的误报条数不算结论**。

### 5.1 四类计数

| 类别 | 条数 |
|---|---|
| 真在途 | |
| 真缺陷 | |
| 窗口已关闭 | |
| 误报 | |
| **总样本数** | |

### 5.2 两个比率

| 指标 | 定义 | 值 |
|---|---|---|
| 判对数 | 真在途 + 真缺陷 | |
| 误报率 | 误报 ÷ 总样本数 | |

计数必须自洽：`真在途 + 真缺陷 + 窗口已关闭 + 误报 = 总样本数`。
「窗口已关闭」两边都不算——它既不是判对（没帮上忙），也不是误报（没说错话）。

### 5.3 判定规则（写死，不许绕）

1. **没有分母的误报条数，不得作为「能否接 CI」的依据。**
   「这周有 5 条误报」在 5 条样本里是灾难，在 500 条里可用——单看条数无法区分。
2. **总样本数 < 20 时，一律写「样本不足，不作结论」。**
   不拿 3 条样本推误报率，也不拿 8 条样本说「趋势向好」。
3. 达到 20 条后再看两件事，缺一不可：
   - 误报率是否可接受（建议门槛 ≤10%，一周后按实际数据再定）；
   - 误报原因码是否**分散**：集中在单一码 → 修那条降级分支后重测；
     **分散在多码 → 不接 CI**，说明判别式本身不稳，接进去只会制造噪音。
