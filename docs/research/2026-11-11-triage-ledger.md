# 在途半成品判别器 · 只读试用台账（2026-11-11 起一周）

**性质**：只读、人工、不进 CI、不作门禁。判别器 `scripts/triage_failure.py` 恒以
退出码 0 结束，只打印结论行；本台账只记录**人**核对后的结论。

## 一、谁在什么时候跑

- **触发点**：每次 `scripts/run_all_tests.sh` 出现 FAIL 之后，由**当次改动者**立刻跑一次
  （同一台机器、同一工作区，越早越能对上「当时的工作区状态」）。
- **频率**：不设定时任务；没有失败就没有样本，空跑没有意义。
- **准入**：一周内只在本地跑，不改任何测试/CI 配置。一周后按「命中是否全为真在途、
  有无误报」决定是否接进 CI 失败摘要。

## 二、怎么跑

```bash
# 失败时 run_all_tests.sh 会打印一行 junitxml 绝对路径，直接喂给它：
python scripts/triage_failure.py --junitxml scratch/test-logs/pytest_tests_g0.xml
```

输出三态：`疑似在途半成品` / `不确定` / **不发声**（符号在 HEAD 里存在 = 真缺陷，交给人看）。

## 三、记什么

每跑一次，向 §四 追加一行；「人工核对结论」必须落到下面四类之一，不许写「待定」：

| 结论 | 含义 | 后续动作 |
|---|---|---|
| `真在途` | 符号只存在于工作区未提交改动 | 记下写盘线，等其收尾后复跑；不报产品红 |
| `真缺陷` | 符号在 HEAD 存在，判别器不发声，红是真的 | 按正常流程修 |
| `窗口已关闭` | 跑的时候符号已写进工作区，异常来自更早的中间态 | 复跑确认绿即可，不追 |
| `误报` | 判别器判了「在途」但实际是产品缺陷 | **必须记**，这是评估是否接 CI 的唯一依据 |
