# 可发现性盘点（2026-11-05）

范围：Python/PyQt6 桌面端（`desktop/`）。目的不是加功能，而是让已有能力**被找到、
被理解、被触发**。文中的数字都是当场从代码/注册表统计出来的，不是宣传口径。

## 二、快捷键盘点

单一事实源：[desktop/shortcuts.py](../desktop/shortcuts.py)。`main_window` 里
18 个 `QKeySequence(_key(...))`，与登记表一一对应（`tests/test_shortcuts_guard.py`
反向核对；本次还把原先散落的 `QKeySequence("A")` 收回登记表）。

按分区（41 条；其中 13 条是频谱焦点内的局部键）：

| 分区 | 已配键 | 无快捷键（括号内是原因） |
|---|---|---|
| 文件 | `Ctrl+C` 连接设备、`Ctrl+D` 断开、`Ctrl+Q` 退出 | — |
| 视图 | `Ctrl+Shift+W` 瀑布、`F11` 全屏、`A` 全天模式、`Ctrl+Shift+P` 星象仪、`Esc` 星象仪退出 | 重置窗口位置（低频救援入口） |
| 工具 | `Ctrl+Shift+F` FM 扫频、`Ctrl+R` 录音、`Ctrl+Shift+N` NTRIP、`Ctrl+Shift+G` 连 GNSS、`F1` 关于 | 断开 GNSS、开始/停止跟踪、更新 TLE（成对或联网/危险，避免误触） |
| 帮助（新增入口） | — | 三步上手、能力目录、快捷键一览（刻意不抢 F1，F1 保留给「关于」） |
| 面板 | — | 恢复出厂布局（破坏性，要求点击确认） |
| 顶栏 | `Ctrl+Shift+S` 保存布局、`Ctrl+Alt+V` 新建 VFO、`Ctrl+Tab` 切主听、`Ctrl+M` 静音、`Ctrl+Shift+R` 回放 | 删除布局（破坏性，内置布局置灰） |
| 频谱（焦点内，`scope="spectrum"`） | `A/N/F/W/C` 切 AM/NFM/FM/WFM/CW、`S` LSB、`Shift+S` USB、`← → ↑ ↓` 调谐、`,` / `.` 滤波档 | — |

**键位归属规则：焦点在哪，局部优先。** 同一键序列可在不同 scope 各登记一条
（`A` 既是全天模式也是频谱 AM）：
- 频谱控件自身获焦 → `A` 归频谱的 AM 解调，主窗全天模式不抢键；
- 频谱没有焦点 → `A` 归主窗，进入全天模式。

实现是 Qt 上下文优先级而不是 `keyPressEvent` 拦截：频谱侧统一装成
`QShortcut` + `Qt.WidgetShortcut`（只在父控件自身获焦时匹配，是最具体的
上下文），主窗侧仍是 `WidgetWithChildrenShortcut`，并在触发槽里跳过
「焦点属于频谱局部键作用域」的歧义兜底。反证见
`tests/test_shortcut_focus_priority.py`：频谱获焦按 `A` 解调变 AM 且
`all_sky_active` 保持 False；无频谱焦点按 `A` 真的进入全天模式。

## 三、能力清单盘点

- **没有**任何"能力目录"界面。`面板` 菜单只列 10 个面板名（频谱/天空模式/气象云图/
  模块信号流/卫星跟踪/新时空/ADS-B/控制/状态/AI 助手），没有一句说明。
- 解调模式下拉 9 项（来自 `mode_registry`）；数字解码能力表 10 项
  （`decode_router`，含真样本/合成链/无样本证据等级）；长尾解码器注册表 3 项
  （POCSAG/ACARS/VOR）。
- AI 工具面：MCP `tools/list` 82 个工具、14 个域（本次实测 `_build_tool_table`）。
  桌面 AI 面板本身不展示工具目录，用户只能"猜它能干什么"。
- **诚实缺口**：`decoder_registry` 的 3 个解码器都未接主调度；POCSAG/ACARS 只能走
  `python -m mbdsdr_ai --decode-file --mode ...`，VOR 无任何入口。能力目录对这 5 条
  （含 FT8/APRS 未接线、2 个空工具域）标「暂不可用」并写原因，不冒充可用。

| 解码 | 数字解码 10 + 长尾解码器 3 + MCP 域 2 | 15 |
| 卫星 | 面板 2 + MCP 域 2 | 4 |

| 录制 | MCP 域 1 + 快捷操作 2 | 3 |

每项都有一句话说明和触发方式（菜单路径 / 快捷键 / AI 工具名 / CLI）。目录里的

MCP 域摘要），不在帮助面板里另抄一份。

## 四、帮助 / 文档入口盘点

- **关于框**（`F1`，工具菜单）：静态版本信息 + 许可证外链；**没有用户手册/功能文档入口**，
  也没有快捷键清单。
- **文档**：`docs/` 有大量开发文档，但桌面端没有任何"打开文档/用户手册"入口。
- **tooltip**：14 个文件共 98 处。风格不统一：
  - 好的：`bookmark_panel`「先在列表里选中一条书签」、`main_window`「回到频谱主页」
    —— 说了什么时候能用/会发生什么；
  - 差的：`main_window`「解调模式」、`device_panel`「采样率 Hz」—— 只是名词复述，
    没告诉用户"改它会发生什么"。
- **空态**：无设备横幅（"正在枚举 SDR 设备…若未自动连接，请点击工具栏「连接」或按
  Ctrl+C"）是唯一的空态引导；其余多为 `--` 或空列表，缺少"为什么空 + 怎么办"。
- **首次引导**：无。（原 S1 首启提示只是一行横幅，且挂在频谱页。）

### 本次新增：三步上手 + 统一文案风格

「帮助 → 三步上手」一页看完：连接设备（键位现取 `shortcuts.py`，没硬件就显示未连接，
**不演示假信号**）→ 看频谱/听声音（说明模式下拉、拖动/滚轮、音量）→ 打开天空模式
（键位现取，搜索框示例）。非模态，只在用户点菜单时出现，不挡操作。

统一风格约定（新增文案 + 审计基线）：

> **做什么** + **为什么 / 什么时候可用** + **怎么办**。
> 例：`bookmark_panel`「先在列表里选中一条书签」；能力目录空态
> 「没有匹配的能力。换个关键词（例如「FT8」「卫星」），或把分类切回「全部」再试。」

## 七、护栏与反证

`tests/test_discoverability_help.py`（15 条）+ `tests/test_shortcuts_guard.py`（10 条）：

- 目录 source 集合 == 各注册表集合（面板/解调/数字解码/长尾解码器/14 个工具域/快捷操作）；
- 每个面板行必须与 `PanelSpec.summary` 逐字一致（删说明即红）；
- `unavailable` 必须写原因且 trigger 以「无」开头；`available` 必须有真实触发；
- FT8/APRS 依赖为空 → 必须标不可用且提到 `not_implemented`；VOR 必须标未接线；
- 静态能力（PTT / 天体搜索）用源码符号反证（`self.tx_button`、`_build_search_widgets`）；
- 快捷键面板：41 条每条恰好出现一次，显示键位逐字等于登记表，无键项必须有原因；
- 三步上手的键位仍登记在 `shortcuts.py`，且第一步明确"不伪造"；
- Qt 冒烟：帮助/快捷键面板非模态、构造时不显示、搜索/分类过滤、空态切换正确；
- `test_shortcuts_guard.py` 全绿（含原先失败的 2 条）。
