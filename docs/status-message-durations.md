# 状态栏提示时长口径（唯一登记处）

本文件是 `desktop/main_window.py` 中 QStatusBar `showMessage` 时长的**唯一口径**。
其他线若要引用数字，直接引用本文，不要再自己 grep 一遍。

- 代码常量：`desktop/main_window.py` 模块顶部 `MSG_QUICK / MSG_NORMAL / MSG_IMPORTANT`
- 测试守卫：`tests/test_status_message_durations.py`（AST 扫描，不靠正则）

## 1. 三档常量

| 常量 | 毫秒 | 语义 |
| --- | --- | --- |
| `MSG_QUICK` | 2000 | 一眼读完的瞬时反馈（模式切换、已清空、扫频进度） |
| `MSG_NORMAL` | 4000 | 普通结果（已保存、已应用、一般失败） |
| `MSG_IMPORTANT` | 8000 | 需要用户注意（失败、断开、注意事项） |

`timeout=0` 只用于**必须常驻**的提示（当前 3 处「回放中」：每帧进度覆盖，
直到用户停止），且调用处必须有行内注释说明常驻理由。

## 2. 终态分布（AST 实数，共 107 处调用）

| 类别 | 处数 |
| --- | --- |
| `MSG_QUICK` | 4 |
| `MSG_NORMAL` | 65 |
| `MSG_IMPORTANT` | 34 |
| 变量透传（`timeout` 形参，由调用方决定） | 1 |
| 显式常驻 `timeout=0` | 3 |
| **合计** | **107** |

其中「设备已断开」一处原为 15 s，已降为 `MSG_IMPORTANT`(8 s)：原意图只是
「比普通提示多留一会儿」，不需要 15 s 这种量级；8 s 足够读完且不长期遮挡。

## 3. 两条数字纠正（重要）

1. **107 是 AST 实数，111 是 grep 行数。** 111 里含注释/文档字符串中出现的
   `showMessage` 字样；真实调用点只有 107 处。引用时请写 107。
2. **「2 秒的错误提示升到 4 秒」没有落点。** 逐条核对后，原文里 2 s 的调用
   都不是错误消息（没有错误文案落在 2000 ms 档），因此这条不构成一次改动；
   终态分布里 QUICK 的 4 处均为非错误提示。

## 4. 如何复核

```
python -m pytest tests/test_status_message_durations.py -q
```

测试断言三件事：

- 三个常量已注册且数值为 2000 / 4000 / 8000；
- 每个 `showMessage` 调用都显式给了时长（第二实参或 `timeout=`），单参即失败；
- 字面量时长只允许等于三档之一；`0` 必须显式 `timeout=` 且调用行附近有注释；
  `MSG_*` 名字必须已登记。
