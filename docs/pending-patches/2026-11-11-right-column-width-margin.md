## 一、脆弱点是什么

B（`收藏当前频率` → `存为书签`，按钮 154→114）落库后：

| 项 | 值 |
| --- | --- |
| `rightColumnBody` 最小宽 | **309** |
| 右栏滚动视口宽 | **310** |
| 余量 | **1 px** |
| 三窄档（1000 / 1265 / 1440）横滚 | 无 |

1 px 不是「达标」，是「刚好没翻红」：右栏任何一处宽度再涨 2px，横向滚动条就回来，而且 `rightColumnScroll` 是 `ScrollBarAsNeeded`——没有缓冲，没有断言会先红。

## 四、两条备选（按裁定① 写入结论）

### 备选 A（100% 档做厚余量）：书签组两按钮改竖排

- 改法：`control_panel.py` 书签组那一行 `QHBoxLayout` → `QVBoxLayout`（或 `QGridLayout` 单列）。
- 收益：书签组 285 → **258**，body → **282**，余量 1 → **28**。
- 代价：多占一行高度（按钮 28 + 间距 9 ≈ **+37px**）。1000×680 下右栏本来就靠纵向滚动承载 20 节长列，这一改只是让滚动更早开始；但它会把「书签组」视觉抬高一档，属视觉改动。
- 边界：**救不了 150%**——150% 的瓶颈是接收组 321，与书签无关。

### 备选 B（真正修 150%）：接收组的 DC/IQ 复选框换行

- 位置：`control_panel.py` 接收组「DC 去除 / IQ 平衡」那一行。
- 改法：两个 `QCheckBox` 由横排改竖排（或 `QGridLayout` 两行）。
- 收益：行宽 273 → 138，接收组 321 → **249**，body 在 150% 下回到 **309**（仍是 1px）；150% 的横滚消失。
- 代价：接收组高度 +~36px（同样换来"更早滚动"）；视觉上这组本来就密，两行复选框会显得更松散。
- 若两者都做：100% 与 150% 同时回到「书签 258 / 接收 249」，body = 282（28px 余量），宽度这条线才算真收口。

5. 反证：把改动单独回退，150% 档必须重新出现 `hscroll_visible == True`（防止只改了文案却把余量记成"已修"）。
