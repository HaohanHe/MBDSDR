# 限制登记补充：本机 FC0012 收不到 1090 MHz（ADS-B 真机验收只能外部取证）

> 目标文件：`docs/limitations-register.md` · §1 待真机 · 第 L3 行（本文件**不直接改**
> 共享台账，交由限制总账 owner 合并）。
> 生成时间：2026-11-06；执行人：解码流水线 P5。
> 触发任务：查清「本机三次实采 0 帧」是硬件到不了还是采集链不对。

## 1. 实测结论（2026-11-06，本机 RTL2832U + Fitipower FC0012，SN 77771111153705700）

跑前按 `docs/hw-acceptance.md §4` 自检：SDR 相关进程**为空**，PnP `Status=OK`；
跑后同两条命令复检：进程仍为空、PnP 仍 `OK`（句柄无残留）。

逐频点单进程实测（`rtlsdr.rtlsdr.RtlSdr`，2.4 MS/s，AGC，写频后回读 + 读 32768 样本）：

| 请求频率 | 回读频率 | 结果 |
| --- | --- | --- |
| 900.000 MHz | 900.000 MHz | OK，rms -28.76 dBFS |
| 945.000 MHz | 945.000 MHz | OK，rms -27.73 dBFS |
| 948.000 MHz | 948.000 MHz | OK，rms -25.87 dBFS |
| **948.500 MHz** | **948.500 MHz** | **OK，rms -8.12 dBFS（本机实测可用上限）** |
| 948.600 MHz | — | 失败 |
| 950.000 MHz | — | 失败 |
| 1000.000 MHz | — | 失败 |
| **1090.000 MHz** | — | **失败** |

失败时回读为零、无实际调谐发生，原始报错（逐字）：

```
rtlsdr.rtlsdr.LibUSBError: <LIBUSB_ERROR_IO (-1): Input/output error> "Could not set center_freq to 1090000000 Hz"
[FC0012] no valid PLL combination found for 1090000000 Hz!
```

948.6 / 950 / 1000 MHz 的报错同构（仅频点数字不同）。

**判定：硬件物理覆盖不到 1090 MHz。** FC0012 的 PLL 组合在 948.5 MHz 之后失效，
1090 MHz 连“写频成功”都拿不到，更不存在“写进去了但收不到”的可能。
因此本机三次 1090 MHz 实采 0 帧**不是采集链参数（采样率合法性/格式/中心频偏）问题**，
是硬件上限问题；无需也未往下排查采集参数。

> 口径修正：既有台账与 `docs/real_hw_acceptance_20261103.md` 写的「上限约 948.6 MHz」
> 偏宽松——948.6 MHz 本身就已失败，实测可用上界落在 (948.5, 948.6] MHz 之间。

## 3. 证明边界（与 ADS-B any-fs 对拍同口径）

- 能证明：本机这颗 FC0012 在 1090 MHz **不可调谐**，因此本机「三次实采 0 帧」的归因是硬件上限。
- 不能证明：ADS-B 解码链本身的能力上限——那部分由 dump1090 官方 OTA 实录
  （`antirez/dump1090` `testfiles/modes1.bin`，2 MS/s u8，SHA-256 `3a33e160…3094`）对拍背书，
  **该样本不是本机录制**，只证明解调/重采样路径与外部真值一致，**不构成本机 1090 接收能力证据**。
