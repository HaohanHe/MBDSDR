# 第二轮深度审查 — `mbdsdr_ai/cw_decoder.py`

- 文件：`mbdsdr_ai/cw_decoder.py`（168 行）
- 审查范围：Morse 码表、1:3:7 时长比例、检测算法、WPM 估计、手键鲁棒性、fldigi 兼容性、空壳识别
- 审查方式：逐行静态阅读 + 用 `encode_cw` 生成信号喂回 `decode_cw` 做闭环复现

---

## 总览结论

这是一份**实验室可跑通、真机基本不可用**的最小实现。码表本身正确，但解码算法是 `abs() + 盒窗平滑 + 单阈值比较`，没有 Goertzel/FFT，没有迟滞，没有最小段长，单位点长估计存在系统性偏差；更严重的是**词间隔切分逻辑会把空格插到错误位置**、**参数 `wpm` 被接收但完全不使用**、**测试信号生成器以 ~220 WPM 而不是注释声称的 12.5 WPM 输出**。这三点合起来正好解释"合成等长信号通过、真实手键失败"。

---

## 真 Bug（会导致错误输出）

### B1. 词间隔把空格插到上一个字符**之前**，不是之后
`mbdsdr_ai/cw_decoder.py:117-124` 与 `mbdsdr_ai/cw_decoder.py:131-136`

切分时，遇到 ≥6u 的停顿，把**当前正在累积的字符**（即上一个词的最后一个字符）以 `kind="word"` flush：

```python
117:    if d >= unit * 6.0:          # 字间隔
118:        if cur_mark:
119:            letters.append(("".join(cur_mark), "word"))
120:            cur_mark = []
```

但拼字符串时，`kind=="word"` 导致空格被 append 在字符**之前**：

```python
133:    if kind == "word":
134:        text_parts.append(" ")   # 先插空格
135:    text_parts.append(ch)        # 再插字符
```

**复现**：`encode_cw("AB CD")` → `decode_cw(...)` 返回 `"A BCD"`（期望 `"AB CD"`）。空格落在 A 与 B 之间，而不是 B 与 C 之间。

**后果**：任何含两个以上字符的词，词尾字符都会被"甩"到下一个词开头；`.strip()` 只消掉首尾空格，中间错位无法恢复。这是真机上阅读完全错乱的头号原因。

### B2. 单位点长估计在"dah 占多数"时被系统性抬高，把数字/短码全部错判
`mbdsdr_ai/cw_decoder.py:98-103`

```python
98:    dit_samp = statistics.median(on_durs)          # 含 dah
100:   short_marks = [d for d in on_durs if d < dit_samp * 1.6]
101:   if short_marks:
102:       dit_samp = statistics.median(short_marks)
```

当一个字母/digit 内 dah 多于 dit（典型如数字 `1=.----`、`6=-....`、字母 `O=---`、`M=--`），`on_durs` 的中位数就落在 dah 长度附近；再用 `1.6*median` 过滤时，dah 本身（3u）仍在阈值内（1.6×3u ≈ 4.8u），过滤不掉，`short_marks` 退化成全体，`dit_samp` 被锁在 dah 长度上。

**复现**：`encode_cw("1")`（`.----`）喂回解码器，输出 `"EEEET"`，且 `wpm_est≈213`。
原理：unit 被估计成 3u，于是真实的 1u dit 与 3u dah 全部落到 `d > unit*1.7` 的 dah 判定阈值（5.1u）以下，全部变成 `.`；只有最后一个 3u dah 侥幸被判成 `-`。

**后果**：数字、O、M、Q、Y、G 等多 dah 字符在真机上几乎必然错。真实手键 dah 时长抖动更大，这个偏差会被进一步放大。

### B3. `wpm` 形参被接收但完全未使用 —— 占位参数
`mbdsdr_ai/cw_decoder.py:69`、`mbdsdr_ai/cw_decoder.py:75`

```python
68: def decode_cw(samples, sample_rate=11025, wpm: Optional[float] = None) -> Dict:
75:     wpm: 已知电码速度（字/分）；给定时用它定单位，否则自动估计。
```

函数体内**没有任何一处引用 `wpm`**（已 grep 全文件）。调用方传 `wpm=20` 期望"已知速度时用它定 unit"，实际行为与不传完全一致。

**复现**：`decode_cw(s2, sample_rate=11025, wpm=20)` 与不传 `wpm` 输出逐字节相同。

### B4. 测试信号生成器实际速度 ≈220 WPM，不是注释声称的 12.5 WPM
`mbdsdr_ai/cw_decoder.py:154`、`mbdsdr_ai/cw_decoder.py:156`

```python
154:    单位点长 60 采样（约 12.5 WPM @11025）。
156:    unit = 60
```

60 采样 @11025 Hz = 5.44 ms。按 `wpm = 1200/unit_ms`（line 105）反算 = **220 WPM**。要得到 12.5 WPM，dit 应 ≈96 ms ≈ 1058 采样。注释与实现差 17 倍。

**后果**：闭环自测时解码器在 220 WPM 的理想方波上跑通，就误以为算法可用；真机 12–18 WPM 的手键信号抖动相对单位而言被放大 ~17 倍，所有阈值裕度同时崩溃。这是"实验室绿、真机红"的直接根源之一。

### B5. 编码器词间隔重复叠加，实际产生 10u 而非标准 7u
`mbdsdr_ai/cw_decoder.py:160`、`mbdsdr_ai/cw_decoder.py:167`

每个字母结束都无条件追加 3u 停顿（line 167）；遇到空格又追加 7u（line 160）。于是 "HELLO WORLD" 中 O→W 之间的实际停顿 = 3+7 = **10u**，标准应为 7u。同样让自测的"词间隔"比真机宽裕 ~43%，阈值 6.0 在自测里永远不会误判，真机上 5–6u 的手键词间隔就会被切成字符间隔。

### B6. WPM 公式旁的注释数学错误（公式本身对）
`mbdsdr_ai/cw_decoder.py:105`

```python
105: wpm_est = 1200.0 / unit_ms ...  # PARIS: 1dit=1.2s/50=24ms@12wpm
```

公式 `wpm = 60000/(unit_ms*50) = 1200/unit_ms` 是对的。但注释"1.2s/50=24ms@12wpm"自相矛盾：12 WPM 下一个 PARIS 字耗时 5 s，dit = 100 ms；1.2 s/字 对应 50 WPM。注释会误导后续维护者调错常量。

## 空壳 / 占位

### P1. `dah_ms` 不是测量值，是 `unit_ms*3` 的占位
`mbdsdr_ai/cw_decoder.py:146`

```python
146: "dah_ms": round(unit_ms * 3, 1),
```

返回值看起来像"实测划长"，实际是用估计 unit 乘 3 反推的，没有任何对真实 dah 段长度的统计。调用方无法用它判断解码器是否把 dah/dit 判对了。

### P2. `confidence` 只是"非 `?` 比例"
`mbdsdr_ai/cw_decoder.py:139-140`、`mbdsdr_ai/cw_decoder.py:148`

```python
139: known = sum(1 for c in chars if c["char"] != "?")
140: conf = known / len(chars)
```

不度量阈值裕度、不度量段长与 1:3:7 的拟合度、不度量 SNR。所有字符都在码表里能查到时（哪怕错得离谱，如 B2 的 `1→EEEET`），confidence 永远是 1.0。

### P3. 整个模块没有 Goertzel / FFT / 带通 —— 只是包络检波
`mbdsdr_ai/cw_decoder.py:85-90`

```python
85: env = [abs(s - mean) for s in samples]
86: env = _smooth(env, max(3, n // 200 | 1))
89: lo, hi = sorted(env)[int(n*0.1)], sorted(env)[int(n*0.9)]
90: thr = lo + (hi - lo) * 0.4
```

docstring（line 5-13）自称"时域包络检测"，这点诚实；但意味着：
- 没有载波中心频率参数，无法选台；
- 多个 CW 信号同段出现时全部混叠成一个包络；
- 对 700 Hz 单音，盒窗 win=n//200 ≈ 55 采样 ≈ 5 ms，平均 ~38 个载波周期，能勉强抹平载波，但这不是"能量检测"，且对频偏、衰落、QRM 完全无抵抗；
- 与 fldigi 的 Goertzel 通道根本不是同一类算法，不存在"兼容解码"一说。

## 与"实验室绿、真机红"直接相关的薄弱点

| 现象 | 代码位置 | 真机后果 |
|---|---|---|
| 阈值单门限、无迟滞 | `:90`、`:57` | 包络在阈值附近抖动时，一段 mark 被切成多段短 mark，错判成连续 dot |
| 无最小段长去抖 | `:51-65` | 单个采样毛刺成为 1-sample 的"dit" |
| 阈值用 10/90 分位，长停顿会把 hi 拉低到接近 lo | `:89-90` | 慢拍/长间隙时阈值被噪声触发，全是 spurious dit |
| dit/dah 分界 1.7u，dah/dit 抖动 ±30% 就越界 | `:114` | 手键 fat dit 被当 dah，thin dah 被当 dit |
| 字符间隔 2.5u / 词间隔 6.0u（标准 3u/7u） | `:117`、`:121` | 手键 2u 间隙被并成同一字母，5u 词间隙被切成字符 |
| 单位估计被 dah 拉偏（B2） | `:98-103` | 数字和多 dah 字母系统性错 |
| 自测信号实际 220 WPM + 10u 词间隔（B4、B5） | `:154-167` | 自测覆盖率虚高，真机参数裕度全失 |

## 与 fldigi / 标准软件兼容性

- **没有音调频率参数**：fldigi 默认在 700–800 Hz 窄带内做 Goertzel；本解码器只看幅度包络，喂给它 raw SSB 音频会把所有信号都当 CW。
- **没有 AGC / 噪声门**：fldigi 有强 AGC 和符号同步；本解码器阈值只按整段 10/90 分位定一次，段落间不重估。
- **1:3:7 比例**：码表内映射正确，但时长阈值（1.7 / 2.5 / 6.0）与标准 1 / 3 / 7 不严格对齐，没有为手键抖动留迟滞区间。
- **prosign 缺失**：`MORSE_TABLE` 没有 `=`(`-...-` BT)、`;`(`-.-.-.`)、`"`(`.-..-.`)、`$`、下划线等；fldigi 解码这些是日常。

## 建议（按优先级）

1. **[必修]** 修 B1：把 `kind="word"` 的空格改为 flush 之后再补一个空格，或在拼字符串时把空格 append 在字符**之后**。
2. **[必修]** 修 B2：先用对数直方图/最短 1/3 分位估计 unit，或对 on_durs 做 k-means(2) 分成 dit/dah 两簇，取小簇中位数；不要用全体中位数。
3. **[必修]** 修 B3：要么真正使用 `wpm` 参数（`unit = sample_rate * 60 / (wpm*50)`），要么从签名删掉，别做假参数。
4. **[必修]** 修 B4/B5：把 `encode_cw` 的 unit 改成与 `sample_rate`、目标 WPM 联动；空格事件不要在字母 3u off 之外再叠加 7u，应替换。
5. **[应修]** 加迟滞：上阈值 vs 下阈值（如 thr_high / thr_low = thr ± 20%），并加最小段长（如 <0.3u 的段直接丢弃）。
6. **[应修]** 在函数内加 `tone_hz` 参数，对 samples 做 Goertzel 或带通 + 整流，而不是裸 `abs()`。
7. **[建议]** 补全 prosign 表；把 B6 注释改成正确数字（12 WPM → 100 ms/dit）。
8. **[建议]** `confidence` 应结合段长与 1:3:7 的卡方拟合度，而非非 `?` 比例。
