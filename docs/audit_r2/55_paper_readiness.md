### 4. 弱模型实验：是否真实验证了弱模型？是否有强模型对比？

**判定：弱模型实验设计严重不足，无强模型对比**

- **[空壳] 仅 10 个用例，各跑 1 次** — `experiments/exp_weak_model_toolcall.py:46-61`：
  - 10 个测试用例（摩尔斯编码、卫星过境预测、APRS 编码等）
  - 每个用例仅调用 LLM **一次**，无重复试验
  - 无置信区间，无统计显著性

- **[真bug] 工具集被人为裁剪** — `exp_weak_model_toolcall.py:38-42`：
  ```python
  names = {c[1] for c in CASES}
  schemas = [... for t in ag.tool_registry.list_tools() if t["name"] in names]
  ```
  模型只看到与当前题目相关的 1 个期望工具 + 少量干扰。实际 agent 有数十个工具（`sdr_tools.py` 278KB）。这是低干扰环境下的乐观测试，不能代表真实场景中的工具选择难度。

- **[真bug] 无随机种子，不可复现** — LLM 输出非确定性，每次运行结果不同。CSV 中 100% call/pick/args 通过率（`paper/experiments/weak_model_toolcall.csv`）是单次运行结果，可能不可重复。

- **[占位] 无强模型对比** — 论文第 302 行声称"使用弱模型（Qwen3.6-35B-A3B）与强模型（如 GPT-4o）分别连接"，但：
  - 实际实验脚本仅用 Qwen/Qwen3.5-4B（`exp_weak_model_toolcall.py:35`）
  - 第 304 行的"预期结果：强模型成功率 >95%"是预期值，非实测
  - 无 GPT-4o/Claude 等强模型的对比数据

- **[真bug] 100% 通过率过于完美** — `weak_model_toolcall.csv` 全部 True，与"弱模型"定位矛盾。结合工具集裁剪 + 测试用例过于简单（题目中直接包含了所有参数值），该结果不具说服力。

### 7. 创新性："AI 定义无线电"创新点是否有足够技术深度？

**判定：概念新颖但技术深度偏浅，属于系统集成/架构类贡献**

- **创新点定位**（论文第 40-51 行）：
  1. AIDR 工作定义（概念层面）
  2. 全栈参考实现 MBDSDR（工程层面）
  3. 人在回路双向指令流（交互范式）
  4. 固件级 MCP 工具发现（工程优化）
  5. 8 个实验验证（**未完成**）

- **与现有工作的区分**：
  - vs GR-MCP（2025）：GR-MCP 是 GNU Radio 的软件包装层，MBDSDR 是固件级 MCP + 自研硬件。区分明确。
  - vs MCP-IoX（arXiv 2505.01834）：IoX 是模型层专家网络，MBDSDR 是全栈硬件-软件协同。区分明确。
  - vs MX-AI（arXiv 2508.09197）：MX-AI 面向运营商 O-RAN，MBDSDR 面向消费级/教学。场景不同。

- **[建议] 技术深度不足的问题**：
  - 无新信号处理算法（CFO、AMR、SSTV 均为经典算法的复现）
  - 无新 ML 架构（AMR 用 KNN k=5，特征工程手工设计）
  - 无新的 LLM 推理/规划方法（直接用 function calling + MCP）
  - 核心贡献更接近"系统集成论文"而非"技术论文"
  - WCL 偏好 concise technical contributions，纯系统集成/概念定义类论文在 WCL 接受度较低

- **[建议] 更适合的投稿方向**：
  - IEEE Communications Magazine（概念/综述类）
  - IEEE Access（系统实现类）
  - IEEE SDR Conference / DySPAN（领域会议）
  - 当前状态投 WCL 会因"缺乏技术深度和实验验证"被拒

### 8. 已知"实验室绿真机红"bug 对论文的影响

**判定：致命影响——实验结果不可信，无法支撑论文主张**

- **[真bug] SSTV 识别纯噪声 100% 误报** — `docs/audit_r2/52_experiments.md:127-130`：
  - 所有 SNR 下，纯高斯噪声被误判为 SSTV 制式的概率为 100%（8/8 次）
  - 论文若声称"AI 能自动识别信号制式"，在真实频谱中会频繁误报
  - 这直接否定了论文实验 2（自动制式识别）的可行性

- **[真bug] AMR 训练/测试数据泄露** — `docs/audit_r2/52_experiments.md:39-43`：
  - 训练模板和测试集使用完全相同的参数化生成器（`synthesize_modulation_iq`）
  - 10dB 时 99.17% 准确率是"同分布测试"的必然结果
  - 不能外推到真实信号，论文中的 AMR 性能数字无意义

- **[真bug] PNT 融合是数学恒等式** — `docs/audit_r2/52_experiments.md:102-106`：
  - 实验测量的是逆方差加权的理论最优精度（Cramér-Rao 下界）
  - 无真实接收机数据，无多径/NLOS/时钟偏差
  - 该实验不构成任何实证贡献

- **[真bug] 核心接收链路断裂** — `docs/audit_r2/53_feature_gap_analysis.md:140-145`：
  - 解调后音频无声卡输出
  - 频谱 UI 接合成数据（5 个硬编码高斯峰）
  - 静噪/ANR/增益等调节器存了不用
  - MBDSDR 更像"离线 IQ 分析工具箱"而非实时接收软件

- **综合影响**：论文声称的"AI 驱动无线电接收"核心场景（找台→解调→录音→分析）在真实硬件上**尚未端到端跑通**。实验结果不可信，投稿必被拒。

## 最终判断

**当前状态：不具备投 WCL 条件。**

论文 v0.1 更像是一个**项目白皮书/系统设计文档**，而非一篇技术通信。它提出了一个有趣的概念（AI-Defined Radio）和一个完整的系统愿景，但：

- 没有实验数据支撑核心主张
- 没有真实硬件验证
- 没有基线对比
- 没有统计严谨性
- 核心算法实验存在数据泄露和误报问题

**建议路径**：
1. 先做 2-3 个月的硬件回采和实验补全
2. 聚焦一个核心贡献点（建议：固件级 MCP 的弱模型工具调用可靠性）
3. 用真实 RTL-SDR + ai-sdr Mini 数据替换全部合成数据
4. 补基线对比和统计显著性
5. 然后再投 WCL

预计还需要 **至少 2-3 个月** 的实验工作和论文重写才能达到 WCL 投稿水平。
