## 0. 结论摘要（先看这页）

**一句话定位**

> MBDSDR 是把天球和射频放进同一个时空的观测台：你仰望星空选目标，AI 去谈硬件、调频谱、录信号；屏幕上每个数字都能被后端复算对上。

**两个主导、一个中间层**

| 层 | 主导对象 | 用户看到的 | 不做什么 |
|---|---|---|---|
| 主导一：星象仪 | 时空 | 天球固定、星本来就在那里，动的是摄像机与视场；时间可快转/暂停，过境、光照、轨道、纪元真实 | 不画装饰性天象，不用默认值填未知 |
| 主导二：SDR 工作台 | 频谱 | 调谐、解调、录音、解码、受限发射（带人工门） | 不替代专业频谱仪，不追求硬件全覆盖 |
| 中间层：AI | 协商 | 用户说「我要收这颗星」，模型探测/询问硬件，协商出可行动作 | 不做固定问卷，不编造硬件，不绕过人工门 |

**P0 规模**：11 条。按**当前代码**逐条复核后为：**有 4 条、半有 7 条、无 0 条**。两条主轴的主体已经落地；剩下的 7 条半有集中在站址单一来源、断源状态、录音状态机、真模型协商、收星编排、诚实性反例与动态 UI 边界。`docs/interaction-flows.md` 按真实用户路径审出 **30 条缺陷（阻断 2 / 严重 15 / 一般 10 / 观感 3）**；其中与 P0 相关的 23 条（B1/B2、S1–S15、M2/M4/M5/M10、L1/L3）逐条工单化，见 [PRD-现状对照.md](PRD-现状对照.md) §2。

> 复核口径提醒：审计文档与代码存在时间差。当前代码里 **B1、S2、S3、S5、S13、S15 改动在位**（详见对照表"现状"列），全星表 UI 也已接线（`desktop/rf_sky_view.py:3268-3292/3320-3345`）；`docs/star-catalog.md` §7 第 7 条仍写"UI 接线未做"，属**文档滞后**，以代码为准并应在该文档补记。

**三条硬约束（任何功能不得违反）**

1. **不许假数据**：没有证据的字段一律「未知」，不得用默认值、示意图或"像真的"渐变填充。
2. **不许静默**：空结果、截断、限幅、降级、拒绝，都必须在界面上说清「为什么、还差什么、还能做什么」。
3. **显示可复算**：界面读数必须能被后端同源独立算一遍，并按显示精度半格内对上。

**本 PRD 明确否掉的三件事**（用户已明确否决，不得再提）

- 用固定流程/预设问卷替代 AI 协商；
- 把「不可用」包装成成功（`success=True` 但无数据、无产物）；
- 用「什么都能干」的定位替代明确的非目标用户。

## 1. 定位与用户

### 1.1 产品定位

MBDSDR 是**单机桌面观测台**，不是在线服务、不是专业仪器软件、不是卫星解码大全。它用一个程序承载两件事：

- **看天**：真实星表 + 真实历表 + 真实轨道，时间可操控；
- **收星**：真实 SDR 链路 + 真实解调/录音，由 AI 把"想收哪颗"翻译成"现在能做什么"。

两件事共享同一个**目标上下文**：你在天空里选中的那颗星，就是频谱侧要调的那颗星。

### 1.2 目标用户

| 用户 | 场景 | 成功的样子 |
|---|---|---|
| 业余无线电/卫星爱好者（有 RTL-SDR、可能有云台） | 晚上收 NOAA/Meteor/ISS，白天调 FM/短波 | 说一句话或点一下，链路就对准了；失败时知道缺哪件硬件 |
| 天文爱好者（可能没有 SDR） | 看今晚过境、看星野、控时间 | 天空是真的、时间是可控的、读数经得起核对 |
| 科普教学/社团（一台 Windows 笔记本 + 一根棒） | 课堂演示、社团活动 | 12 分钟内能讲完一条完整链路；断网也能演 |
| 独立开发者/研究者 | 需要可复算、可导出的观测记录 | 每个结论带来源、时刻、站址与证据 |

### 1.3 非目标用户（谁不该用它）

| 非目标 | 原因 | 他们应该用什么 |
|---|---|---|
| 需要 WebSDR / 多人在线共用接收站的人 | 本产品是单机桌面，不做账号、多租户、并发接入 | WebSDR 类服务 |
| 需要专业射电天文测量、干涉、测光精度的人 | 星表只到 V≤9、无测光校准、无表面亮度模型 | 专业测量软件 / 巡天数据管线 |
| 需要 90+ 卫星全谱解码的人 | 解码广度远不及 SatDump 类工具 | SatDump / 专用解码器 |
| 需要通用发射机、竞赛级发射工作台的人 | 发射是受限能力，默认拒发，必须人工门 | 通用 SDR 发射软件 |
| 只想看"像银河的屏保"的人 | 没有银河数据就不画银河（见 L25/L28） | 星象仪娱乐软件 |
| 手机/浏览器/云同步用户 | 当前交付面是 Windows 桌面优先 | 移动端应用 / 网页版 |

> 这条非目标表是范围控制工具：任何新需求先问「它服务上面四类目标用户中的哪一类」，答不上来就不进 P0。

## 2. 问题与产品决策

### 2.1 观察到的问题（有仓库证据）

| # | 现象 | 证据 | 对用户的影响 |
|---|---|---|---|
| 1 | 频谱操作负担高：调谐、带宽、增益、VFO、解调链要用户自己拧 | 频谱面板有 30+ 可交互控件（`docs/interaction-audit.md` 遍历 127 个动作） | 新手停在"频谱不会看"，到不了"收到信号" |
| 2 | 天空与频谱是两套世界：天空按时间引擎算，部分工具按墙钟算 | `docs/limitations-register.md` L23：同一时刻两工具给出不同可见结论 | 用户看到"天上明明有"，AI 说"不可见" |
| 3 | 能力缺口容易被"看起来正常"掩盖 | `docs/limitations-register.md` L24–L34：白天整层消隐、无银河、DSO 仅符号、受晒未知 | 用户把"简化模型"当成"真实观测" |
| 4 | 硬件现实与界面状态可能分裂 | 站址有两个输入面（见 P0-05 证据）；无设备时按钮置灰但理由分散 | 用户不知道到底缺什么 |
| 5 | AI 工具面很大但真实模型未验 | 495 个工具、404 可跑/91 诚实不可用（`docs/tool-availability.md`）；L12–L15 均"仅自测" | "AI 能收星"目前是工程假设，不是已验证结论 |

### 2.2 产品决策（本 PRD 拍板）

| 决策 | 内容 | 推导 |
|---|---|---|
| D1 | **以「一次收星」为最小完整旅程**，而不是以功能清单为范围 | 用户要的是"收到"，不是"有调谐器" |
| D2 | **AI 只做协商与编排，不做固定流程** | 硬件组合不可穷举，问卷必然漏项（用户明确否决问卷） |
| D3 | **未知即未知**：缺数据的能力不上、不猜、不画 | 红线 1 |
| D4 | **接收类写操作与发射类写操作分级**（见 P0-09 依赖 L18） | 若调谐与发射同门，AI 永远无法完成"收星" |
| D5 | **天空与频谱共享一个目标上下文** | 两个主导必须有接口，否则只是两个软件装在一个窗口里 |
| D6 | **只保证已验证平台与设备**（Windows 优先；FC0012 七环、NanoVNA SOLT 等） | 硬件广度不是本产品的竞争力 |

### 2.3 期望的可观察结果

- 新用户能在**不打开频谱**的情况下完成一次卫星接收（或得到明确"缺什么"的结论）。
- 任一时刻，天空视图、过境列表、AI 工具给出的同一条结论**互相一致**。
- 任一失败都有稳定错误码、用户可读的一句话、可执行的下一步。
- 任一"看起来有"的能力，都能被一条自动化用例证明它确实有。

**结论**：这不是"别人能力不足"，而是**产品定位分工**。天球侧把"看"做到极致，频谱侧把"收"做到极致；没有人把两者当成**同一个时空的两个面**来设计。现有产品因此都是"半张图"——而半张图不是错，是它们的边界。逐项功能对照见 §9；本节只解释分工、边界与我们的组合方式。

#### 2.4.2 唯一性主张：三条支柱，缺一条都不成立

我们只主张一件事：**把天球与射频放进同一个时空，由 AI 协商把频谱的"烦"接过去，并用可复算的诚实性契约保证看到的每个数字都能被核对。** 这不是三条并列卖点，而是互相咬合的三根支柱：

| 支柱 | 主张 | 为什么它单独不成立 | 可观测物 | 验收 |
|---|---|---|---|---|
| **A. 同一时空、同一时间源** | 天空、过境、多普勒、受晒共用同一 `TimeEngine` 与同一站址；切换形态不丢目标与时刻 | 只有天球没有射频 = 星象仪；只有射频没有天球 = 接收机；两者都在但时间源分叉 = 两个软件装进一个窗口 | 切形态后目标/时刻不变；同一时刻天空与 AI 的可见结论一致 | AC-01.1、AC-03.4、AC-04.2、AC-05.1、H-8 |
| **B. AI 协商与解读** | 模型在运行时探测能力、只问缺的、给出可执行方案与拒绝理由；不预制问卷、不设死流程 | 没有 A 的上下文，AI 只是通用 SDR 聊天机器人；没有 C，AI 会把"猜"说成"测" | 账本 `known/unknown` 可读；同会话不重复问；拒绝带原因与下一步 | AC-08.1–08.5、AC-09.1–09.4 |
| **C. 可复算的诚实性契约** | 未知即未知、空结果有因、截断/限幅标注、读数半格可复算、证据强度分级 | 没有 A/B，C 只是文档规范；有了 A/B 而没有 C，产品会"看起来很懂"但经不起核对 | 每个读数可被后端独立复算；每个空/缺/限都有文案；发布清单逐条标证据强度 | H-1–H-12、AC-10.1–10.12 |
| **A×B×C 的组合** | A 提供共同上下文，B 把操作负担转成协商，C 让 B 的结论可审计、让 A 的未知不被美化 | 任何一条缺失，另外两条都会退化成"普通功能" | 一次收星旅程里三者同时出现且互不打架 | AC-09.1–09.8（端到端） |

**"凭什么"**：不是凭功能数量，而是凭**组合方式**与**交付门槛**。SDRangel 已经证明"SDR + 卫星跟踪"能做；Stellarium/Gpredict 已经证明"天球 + 时间"能做；SDRangel 也已经证明"模型可调 SDR"能做。没有人把这三件事做成**同一个目标上下文**，也没有人把"可复算"写成**发布门槛**而不是宣传语。我们的护城河是：**同一时空（A）让协商有上下文，协商（B）让频谱不烦人，诚实性（C）让前两者可信**——三者互相验证，拆开就都不成立。

#### 2.4.3 明确承认边界：哪些是别人已有、我们不声称首创

| 能力 | 已有者（出处见 §2.4.1 / 附录 B） | 我们的关系 |
|---|---|---|
| 实时频谱/瀑布 | SDR++、gqrx、SDRangel、SatDump | 使用与学习，不声称首创 |
| SGP4/TLE 轨道与过境预测 | Gpredict（核心能力） | 使用同一公开模型（Vallado/SGP4），不声称首创 |

| 天球渲染、时间倍速、卫星插件 | Stellarium、Gpredict | 不声称首创；机制学习，代码独立实现（MIT） |
| 90+ 卫星解码 | SatDump | 不声称首创，且明确只保留已验证的少数解码器 |
| 模型可调 SDR / MCP | SDRangel | 不声称首创；差异是**协商式**而非命令式，结论落账、拒绝可测 |
| Hamlib 电台/旋转器控制 | Gpredict | 不声称首创；我们只保证已验证设备 |
| 发射能力 | SDRangel | 不声称首创；我们默认拒发、逐次人工门 |
| 多 VFO、广泛硬件支持 | SDR++、gqrx、SDRangel | 不声称首创；不追求硬件广度 |

**本节自我约束**：以上任何一项都不得在对外材料里写成"我们首创"。我们唯一声称的组合是：**A 同一时空 + B 协商式 AI + C 诚实性验收门槛**。

## 3. 范围与优先级

### 3.1 P0：能演示成立的最小闭环

进入条件：用户打开程序，选择形态（星象仪 / 工作台）。
完成条件：**选定一个目标，得到一次可复算的观测结果**（收到信号、看到过境、或得到带原因的拒绝）。
恢复路径：缺 SDR / 缺站址 / TLE 过期 / 云台缺失，四类失败都给出降级方案。

跨天使用、真实硬件长期跑、AI 在真实模型下稳定、真实录音库可迁移。

### 3.3 P2：能交付

补齐已知能力缺口（银河、导览、受晒驱动可见性等）、打包与许可、多环境适配。

### 3.4 明确不做（防范围蔓延）

见 §9。

## 4. 产品模型

### 4.1 核心对象

| 对象 | 定义 | 关键字段 | 谁产生 |
|---|---|---|---|
| 观测站 Station | 一次观测的时空原点 | 纬度、经度、海拔、来源（GNSS/手动/配置）、时刻 | 用户/GNSS |
| 时间基准 Clock | 全程序唯一模拟时刻 | unix、rate、paused、来源（实时/模拟） | TimeEngine |
| 目标 Target | 卫星或天体 | 名称、NORAD/星表 ID、az/el、距离、过境窗口、链路频点 | 天空线 |
| 视场 View | 摄像机状态 | 中心 az/alt、fov、锁定目标、投影 | 天空视图 |
| 链路 Chain | 一条接收路径 | 设备、中心频率、带宽、增益、VFO、解调、录音状态 | 工作台 |
| 能力账本 Ledger | 本次会话确认的硬件现实 | 槽位（sdr/gimbal/gnss/imu/antenna）、状态（available/missing/unknown）、证据、时刻 | AI 协商 |
| 动作提案 Proposal | 一次可执行的方案 | 动作、目标、所需槽位、降级方案、拒绝原因 | AI 协商 |
| 界面动作 UiAction | 模型对界面的唯一合法修改 | 动词、目标面板 id、值、逆操作 | AI/用户 |

### 4.2 双环状态（目标锁定）

两个环语义独立，界面不得让用户误以为两个都在跑。

| 摄像机环 | 跟踪环 | 允许的界面表述 |
|---|---|---|
| 锁定 | 开启 | 「视角跟随 + 调谐跟踪」 |
| 锁定 | 关闭/失败 | 「仅视角跟随，未在调谐」 |
| 未锁定 | 开启 | 「未锁定（仅调谐）」 |
| 未锁定 | 关闭 | 「未锁定」 |

状态迁移规则：

1. 两个环的勾选态、目标、解锁条件互不连带。
2. 换选另一颗星：摄像机跟随新目标并重锁；**跟踪停止且不偷偷换频**，提示「目标由 A 切换到 B，需重新开启跟踪」。
3. 反选目标或站址失效：两个环都收口，并说明原因（反选 / 观测站失效）。
4. 跟踪启动失败或过境结束：主窗口必须回写「未勾选」；若摄像机仍锁定，提示「调谐跟踪已停止（或未启动），摄像机锁定仍保持，不会自动换频」。
5. 摄像机锁定被拒（轨道数据/站址不可信）时，跟踪保持勾选，状态行显示「摄像机：未锁定（仅调谐）」。
6. 设备断开/连接失败：跟踪环停止并回写未勾选；不得出现"界面已断开、后台还在按多普勒写频"的状态（S15）。

### 4.3 时间基准（唯一事实源）

| 用途 | 时间源 | 禁止 |
|---|---|---|
| 轨道/过境/可见性/多普勒/天空绘制 | TimeEngine 模拟时刻 | 直接用墙钟 |
| 超时、文件命名、缓存年龄、NTP 偏差 | 墙钟 | 用模拟时刻 |
| 跨模块传时间 | 显式 UTC 秒（`start_unix`/`at_unix`/`when`/`timestamp`） | 下游各自取 `now()` |

新增或修改任何时间相关功能，必须通过 `tests/test_time_input_guard.py`，并在 `docs/time-source.md` 场景表登记。

### 4.4 能力槽位与状态

| 槽位 | 覆盖硬件 | 探测手段（现有工具面） | 无该槽位时还能做什么 |
|---|---|---|---|
| `sdr` | 接收设备 | `sdr_list_hardware` / `sdr_connect` 状态 | 只给可见性、过境窗口、调谐建议频点 |
| `gimbal` | 云台/旋转器 | `gimbal_modes` / `gimbal_connect` / 姿态回读 | 只调谐不指向；提示需手动指向 |
| `gnss` | 定位模块 | GNSS 连接状态、站址有效性 | 用已配置站址；无站址则拒绝一切地平相关计算 |
| `imu` | 姿态传感器 | IMU 状态工具 | 不影响本轮可行性，只影响指向精度说明 |
| `antenna` | 定向天线 | 用户自述/配置 | 按全向天线处理并标注「未确认增益」 |

状态只允许三值：`available` / `missing` / `unknown`。**`unknown` 不得当作 `available`**。

### 4.5 权限与边界

| 操作 | 谁可以做 | 条件 | 失败表现 |
|---|---|---|---|
| 改界面（显隐/页签/比例） | 模型 | 目标必须在面板注册表内，动词必须受支持 | 明确 ERROR + 原因，不假装成功 |
| 接收调谐/增益/录音 | 用户；模型需人工确认（策略待 L18 拍板） | 设备已连接 | 未连接则置灰 + 理由 |
| 发射（CW/IQ/上行/回放发射） | 仅用户，逐次人工门 | 网关 arm、token、频段白名单 | 区分 `gate_not_armed/gate_expired/gate_revoked/gate_unknown_token/gate_token_mismatch` |
| 改站址 | 用户 | 手动输入或 GNSS | 无站址 = 拒绝地平计算，不猜城市 |
| 导出观测记录 | 用户 | 有产物才允许 | 无产物时保存按钮置灰并说明 |

### 5.1 星象仪：从打开，到"看见今晚 19:42 那颗过境"

**正常路径**

1. 打开程序 → 进入星象仪形态（天空在上、瀑布在下、底部一条 AI 命令条）。
2. 站址已就绪（GNSS 或上次手动填的坐标）；状态卡写明「站址来源 / UTC 时刻 / 本地偏移 / 时间倍率」。
3. 默认 60° 视场，天球按真实时刻渲染；宽视场保持裸眼极限（星表 LOD 不给"凭空冒星"）。
4. 拉远到 180°：看到全天暗星与地平线；拖拽/双击接管摄像机。
5. 输入或点选 NOAA 19：信息卡给出 az/el、距离、过境窗口、调谐频点；过境面板给出下一次 rise（秒级）与峰值仰角。
6. 把时间拨到 ×300：轨迹按模拟时刻重算；锁定目标逐帧直贴并提示「快转下平滑跟随跟不上，已改为逐帧直贴」。
7. 时间跳转 +10 分钟：若目标仍在地平线上，继续锁定并直接贴住；若目标落到地平线下则诚实解锁并说明。
8. 点「📡 调到该星」：链路按多普勒校正调谐（或 AI 协商后执行）；HUD 两行常驻显示视角/调谐状态。

**失败怎么表现（必须可演示）**

| 失败 | 界面 | 禁止 |
|---|---|---|
| 没有站址 | 状态卡「缺少观测站」；只允许赤道坐标浏览；过境/调谐/跟踪按钮置灰并写明「需要观测站」 | 默认某个城市坐标 |
| TLE 过期/失效 | 目标仍可画，但标注「轨道数据过期（dead），不用于精确过境」；过境面板不给假窗口 | 用过期 TLE 当作精确值 |
| 白天看星 | 状态卡「白天·无恒星」；恒星整层不画、不可点选 | 画一个"淡一点的星空" |
| 快转太猛 | 提示「×N 下单帧位移 X°，画面按帧跳进」 | 静默抽动 |
| 锁定被拒 | 状态行「摄像机：未锁定（仅调谐）」 | 显示成两个环都在跑 |

### 5.2 SDR 工作台：从打开，到"录下一段干净的 137.5 MHz"

**正常路径**

1. 打开工作台形态 → 频谱居中，左侧面板页签、右侧控制/状态/AI。
2. 连接设备（无设备时频谱上方有引导横幅，连接按钮高亮）。
3. 设置中心频率、带宽、增益；频谱按 1/2/5 阶梯刻度显示，瀑布滚动。
4. 在 137.5 MHz 附近看到卫星信号：峰值标签、带内 SNR、频段彩带（卫星频段）同时可见。
5. 选择解调（NFM/WFM/AM/SSB/CW 等）并应用；调 VFO 偏移与带宽。
6. 录音 → 落盘为 IQ 文件；录音库列出条目，可回放、可导出。
7. 卫星场景切到星象仪：选星 → 「调到该星」→ 跟踪开启；切回工作台，频谱显示多普勒移动的谱线。
8. 收工：状态栏显示本轮结论（频率、目标、时长、文件路径）。

**失败怎么表现**

| 失败 | 界面 | 禁止 |
|---|---|---|
| 未连接设备 | 频谱上方横幅 + 按钮置灰 + 理由「未连接 SDR，没有 IQ 信号可录」 | 显示一条"平"的假瀑布 |
| 设备被占用 | 状态栏「设备被其他进程占用（LIBUSB_ERROR_ACCESS）」，建议关闭占用进程或换设备 | 静默重试直到卡死 |
| 频率超出设备范围 | 拒绝并写明设备上下限（真实型号能力，不猜） | 夹到边界却当成功 |
| 解调链未下发 | 明确「解调链未应用」，不显示解码产物 | 显示上一次的残留结果 |
| 录音磁盘满/权限 | 失败信封 + 已写入字节数 + 路径 | `success=True` 空文件 |
| 解码缺样本 | 「缺样本，不是解码失败」并给录制路径 | 用合成数据冒充结果 |
| 换设备 | 先断旧后端；「已连接 B」只在读到 B 的数据后才出现 | 界面说 B、数据仍来自 A，旧设备仍被占用 |
| 录音中开始回放 | 自动停录并提示；回放结束不自动续录 | 录音状态假活、零采样写进同一文件 |
| 窗口恢复越界 | 居中/回主屏，并提供「重置窗口位置」 | 窗口出现在屏幕外无法找回 |
| 缺参数（AI 调频） | 报缺参错误，界面不变 | 落到演示频率 98.5 MHz |

### 5.3 AI 路径（贯穿两条主轴）

用户输入「我要收 NOAA 19」。模型：

1. 读账本 → 已知：有 SDR、无云台、站址来自 GNSS。
2. 探测：设备是否连接、频率范围、TLE 新鲜度、当前时间倍率。
3. 只问真正缺的且会改变结论的一项（例如「你的天线是固定的还是手动的？」）。
4. 给出方案：「现在 19:42 过境，仰角 61°；我调 137.5 MHz + 多普勒跟踪；云台缺失，需要你把天线指向 210° SW。」
5. 用户确认后执行；执行结果逐条回填（调谐成功/失败、跟踪开启/失败）。
6. 若中途硬件掉线：停止跟踪、回写勾选态、说明「跟踪已停止，摄像机锁定仍保持」。

**禁止路径**：不问就假设有云台；把 `unknown` 当 `available`；跳过人工门直接发射；用"正在接收…"的文案代替真实产物。

### P0-06 SDR 工作台基本功

- **用户故事**：作为无线电用户，我要能调谐、看频谱、看瀑布、选解调、设带宽增益，并且在没设备时不要装作在收。
- **行为规则**
  1. 两种点击语义：中心模式（点击重调硬件中心）与 VFO 模式（只移动 VFO，画面不动），按钮状态可辨。
  2. 缩放锚定光标；频率刻度 1/2/5×10ⁿ 阶梯 + 自动单位；标签数有上限且不重叠。
  3. 峰值检测：窄峰 + 宽峰双通道，噪声底用分位数/中位数；Top-N 上限；缓存节流。
  4. Max/Min hold 可开关；VFO 带内 SNR 常驻显示。
  5. 解调链选择与应用必须真实下发；未下发不得显示解码产物。
  6. 无 IQ 数据时：峰值/瀑布平滑/书签/频段等按钮置灰并给理由。
  7. 设备能力（频率上下限、增益档位）来自真实枚举，不猜。
  8. 设备切换必须先断开旧后端并停流水线，确认新设备真实出数后界面才显示"已连接"（B1）。
  9. 连接失败/掉线必须禁用依赖控件并显示「已断开（原因）」，不得只改标签（S8/S9）。
  10. 流水线重建不得删除用户创建的 VFO，不得用后端 `status.demod_mode` 覆盖用户选择的解调模式（S3）。
  11. 首次启动的设备引导必须出现在当前可见页（S1）。
- **验收标准**
  - AC-06.1 点击中心模式：硬件中心频率改变且画面跟随；VFO 模式：中心不变、VFO 移动。
  - AC-06.2 在最小/默认/最大三档 span 下，刻度步长均为 1/2/5×10ⁿ，标签 ≤6 且最小间距 ≥1.5 字宽。
  - AC-06.3 合成谱（两窄峰 + 一宽平台）→ 恰 3 个峰、无重复；纯噪声 → 0 峰；带外强峰不抑制带内弱峰。
  - AC-06.4 未连接设备时，所有依赖 IQ 的按钮置灰且 `toolTip`/状态栏写明原因。
  - AC-06.5 频率超出设备范围 → 拒绝信封含设备上下限，不夹边冒充成功。
  - AC-06.6 切换设备：旧后端 `disconnect` 必被调用，旧设备读调用停止，新设备出数后状态才变（B1）。
  - AC-06.7 拔线/连接失败：依赖控件禁用 + 状态「已断开（原因）」+ 重连入口；频谱不保留旧帧冒充实时（S8/S9）。

### P0-07 录音、回放与录音库

- **用户故事**：作为用户，我要把一段 IQ 录下来，之后能找到它、回放它、必要时迁移/清理，且文件名能定位到时刻与频点。
- **行为规则**
  1. 录音只在设备已连接时可用；落盘路径、开始时刻、中心频率、采样率写入元数据。
  2. 失败必须报告已写入字节数、路径与原因（磁盘满、权限、设备掉线）。
  3. 录音库支持列表、迁移、回收站、损坏索引处理；迁移必须先在副本上预演，不碰原件。
  4. 回放发射属于发射能力，必须走人工门；普通回放不等于发射。
  5. 录音与回放互斥：开始回放必须自动停录并提示，回放结束不自动续录（S5）。
  6. 录音中改采样率必须分段落盘或禁止；读取端按 `sample_rate_changes` 分段处理（S4）。
  7. 写盘失败必须停止录音并保留已写部分；磁盘不可用直接拒绝开始（S7）。
  8. 长录音加载不得在 UI 线程同步 `.tolist()`；必须后台/分块（S6）。
  9. 同一秒内的两次录音不得覆盖（文件名加序号/毫秒）（L3）。
- **验收标准**
  - AC-07.1 录 10 秒 → 文件存在、大小与元数据自洽、可在库中列出并回放。
  - AC-07.2 断线中断 → 文件不损坏，状态栏明确「录制中断，已写入 N 字节」。
  - AC-07.3 真实录音库副本迁移预演通过（合成库不算）。

## 7. AI 能力协商规格

### 7.1 触发

| 触发 | 入口 | 必带上下文 |
|---|---|---|
| 用户点天空动作（跟踪/调到该星/云台跟随） | 天空 HUD 按钮 | 目标上下文：名称/NORAD/az/el/标称下行/多普勒/过境窗口/TLE 历元/站址 |
| 用户自然语言（"我要收 NOAA 19"） | AI 命令条 / AI 面板 | 当前选中目标（若有）+ 用户原文 |
| 模型主动检查 | `sky_capability_state` | 会话账本 |

### 7.2 必须探测/询问的内容

| 顺序 | 项 | 探测优先 | 探测不到才问 | 为什么必须 |
|---|---|---|---|---|
| 1 | 会话账本已有结论 | 复用 | — | 不重复打扰用户 |
| 2 | SDR 是否连接、型号、频率范围 | `sdr_list_hardware` / 连接状态 | 问「你现在接的是哪台设备？」 | 决定能否调谐/录音 |
| 3 | 站址是否有效及来源 | 站址事实源 | 问「你在哪里观测？」 | 决定 az/el 与过境 |
| 4 | 云台是否存在、能否回读姿态 | `gimbal_modes`/连接/回读 | 问「天线是固定的还是带云台的？」 | 决定能否自动指向 |
| 5 | TLE 新鲜度 | `tle_integrity.freshness` | 不询问（可刷新则刷新，失败如实报） | 决定过境是否可信 |
| 6 | 时间基准状态 | TimeEngine rate/paused | 不询问 | 快转下结论会变 |
| 7 | 天线/增益（可选） | 配置 | 仅在影响结论时问 | 影响可行性说明 |

**询问原则**

1. 只问「探测不到」且「会改变本轮可行性」的项；能探测的一律不问。
2. 一次只问一句，但一句可含多件硬件（用户可用一句话描述多件）。
3. 用户已回答的写入账本，后续不再问；用户改口覆盖旧结论。
4. **提问由模型发起**：问题必须由模型在运行时根据账本缺口生成；**禁止预设问题清单、禁止固定顺序、禁止固定流程、禁止表单式追问**。产品代码不得内置问题模板、问卷 schema 或表单渲染路径。
5. 用户拒答/不知道 → 记 `unknown`，按 `unknown` 给保守方案，不逼问。
6. 可检查性：源码中不得存在"问题清单/问卷模板"常量；同一硬件组合下两次会话的提问序列不得完全相同；UI 不得弹出表单式追问控件。

### 7.3 结论如何记录

`sky_capability_report` 写入两类记录，挂在会话上：

| 记录 | 字段 | 语义 |
|---|---|---|
| 槽位结论 | `slot`、`state`（available/missing/unknown）、`evidence`、`at` | 本次会话确认的硬件现实 |
| 动作拍板 | `action`、`allowed`、`reason`、`missing_slots` | 本轮能做什么/为什么不能 |

规则：

- 非法 `slot`/`state` 必须拒绝并给原因（现有 `validate_capability_item` 已覆盖）。
- 每条结论必须带证据（探测输出摘要或用户原话），无证据不得写 `available`。
- 会话结束即失效；跨会话不继承（避免陈旧硬件假设）。日志可导出（P1-08）。

### 7.4 拒绝与降级的表达

固定三段式，不允许只说"失败"：

```
结论：现在能不能做（能 / 不能 / 只能做一部分）
原因：缺哪个槽位，证据是什么（未知也要说未知）
下一步：可执行的替代动作（手动指向 / 只给过境 / 换设备 / 刷新 TLE）
```

示例（无云台）：

> 现在能调谐，但不能自动指向。原因是账本里 `gimbal=missing`（你刚才说天线是固定的）。下一步：19:42 过境时我把频率调到 137.5 MHz 并做多普勒跟踪，你需要把天线指向 210° SW、仰角 61°。

错误码复用 `error_catalog`（`NEED_HW`、`not_connected`、`tool_unavailable`、`no_rssi` 等）；发射拒绝复用 `tx_guard` 五个门码。

### 7.5 禁止事项（逐条可测）

| # | 禁止 | 检查方式 |
|---|---|---|
| AI-F1 | 生成固定问卷/固定步骤脚本 | 代码审查 + 用例：同一硬件组合下，两次会话的提问序列不得来自静态模板 |
| AI-F2 | 编造硬件（默认设备、默认云台、默认站址） | 账本无证据时不得出现 `available` |
| AI-F3 | 把 `unknown` 当 `available` | 单测覆盖三值语义 |
| AI-F4 | 静默换目标/偷偷换频 | `TARGET_MISMATCH` 用例 |
| AI-F5 | 绕过人工门发射/写设备 | 写工具只能申请，授权只来自界面真人确认（弹窗，超时=拒绝）；模型参数不得作为授权依据 |
| AI-F6 | 用文案冒充产物（"正在接收/已收到"但无文件/无图） | 成功必须附产物路径或数据指纹 |
| AI-F7 | 未验证的能力说成已验证 | 发布清单标注证据强度（对应 `limitations-register.md` 口径） |

## 8. 动态 UI 与诚实性规范

### 8.1 模型能改什么 / 不能改什么

| 类别 | 允许 | 说明 |
|---|---|---|
| 面板显隐 | `show_panel` / `hide_panel`，目标必须是 `panel_registry` 里的 id | 经菜单勾选同一路径，不销毁控件 |
| 页签/焦点 | `select_tab` / `focus_panel` | 目标页签必须存在 |
| 布局比例 | `set_layout_ratio`（"左:中:右"） | 必须有合法性校验：正整数、段数=3、合计>0 |
| 逆操作 | 每个动作返回 `inverse`；撤销栈与 Ctrl+Z **待实现**（M10） | 回退必须精确恢复旧尺寸；未实现前不得在界面暗示"可撤销" |
| **禁止** | 发射 arm/门 token/频段策略、设备连接与断开、录音启动、任何数据字段、主题/字号、窗口几何、未注册控件 | 动词集合里不存在这些能力（白名单即边界） |

**失败表达**：未知目标/未知动词/非法比例 → `ERROR` + 原因，界面**不变**，不重试。`NOOP`（本来就是这个状态）算成功但要说明"未变化"。

### 8.2 诚实性规范（验收项，P0-10）

| ID | 规则 | 怎么查 | 查什么 | 期望值 |
|---|---|---|---|---|
| H-1 | 外部数据带来源与时效 | 打开 TLE 卡片、星表状态卡、导出 JSON | `epoch` / `fetched_at` / `freshness` / `license` 字段 | 四个字段非空；过期必须写「过期（历元 …）」 |

### 10.2 容量与并发

- 星表：83,479 颗；单次绘制预算 `max_count` 默认 20,000。
- 同时 VFO 数量：`[TBD]`（现状未定义上限，需拍板）。
- 并发：UI 单线程；模型动作经 150 ms 总线排空；录音/解码在后台线程；AI 流式必须可取消。
- 长时运行：≥8 小时连续接收不得内存单调增长（以录音与瀑布缓冲为观察点）。

### 10.3 隐私

| 数据 | 规则 |
|---|---|
| 站址坐标 | 仅本机保存；不上传；导出需用户显式操作 |
| 录音/IQ 文件 | 仅本机；路径与元数据不外发 |
| 会话内容 | 仅在用户配置模型时发送给该 provider；离线模式拒绝 |
| 联网调用 | 逐次可感知（工具名可见）；`MBDSDR_OFFLINE=1` 全拒 |

验收：强制离线 + 网络桩抛错，全链路无出站调用；日志不得含完整路径以外的隐私字段（`[TBD]`：日志脱敏范围）。

### 10.4 平台

- **Windows 优先**（仓库验收环境）；Linux 桌面可用但未系统验收。
- arm64 Chromebook：已有交叉编译，物理机未验（L6），不得宣称支持。
- DPI：`PassThrough` 舍入策略（`desktop/main.py:94-95`）；100%/125%/150%/200% 布局基线必须通过。
- 单机、无安装服务依赖（可选外部程序如 SatDump 需显式提示）。

### 10.5 可访问性

- 正文对比度 ≥4.5:1（WCAG 1.4.3）；已测：default 正文 5.11:1、次级 5.14:1、dark 次级 5.22:1（`docs/design_tokens_mapping.md` §5）。
- 非文本控件对比 ≥3:1（WCAG 1.4.11）。
- 全部主要操作可用键盘完成；快捷键经注册表与冲突守卫（`desktop/shortcuts.py`，`test_shortcuts_guard.py`）。
- 置灰必须带理由（可读文本，不只是图标变灰）。
- 不依赖颜色单一维度表达状态（受晒/地影同时用描边与文字）。

### 10.6 可靠性

- 所有网络请求有连接超时与墙钟硬截止（含 DNS）；离线/超时明确拒绝。
- 不静默重试；重试必须可数、可停、可解释。
- 设备被占用（如 `LIBUSB_ERROR_ACCESS`）必须给用户可执行建议，不循环重连。

### 10.7 健壮性架构（可诊断、可降级、可验证）

## 11. 里程碑与风险

### 11.1 三档里程碑（不设日期，只设出口条件）

**M1 能演示**

出口条件（缺一不算）：

1. 无 AI key、无 SDR 也能完整演示星象仪：真实星表、可控时间、过境面板、诚实空态。
2. 有 SDR 时演示"选星 → 调谐 → 录音 → 回放"。
3. 断网演示：所有联网能力要么本地可用并标注，要么明确拒绝。
4. 三条演示脚本留存（有硬件 / 无硬件 / 断网），每条 12 分钟内。
5. 全星表接入（P0-02 AC 全绿）。

**M2 能自用**

1. 真实 LLM + 真实 SDR 完成一次"一句话收星"（成功或完整降级）。
2. L12–L17 真验销账；L18/L19 策略拍板并落到默认值。
3. 真实录音库副本迁移通过（P0-07 AC-07.3）。
4. 站址单一来源（P0-05 AC 全绿）。
5. 受晒字段接通（P1-01）或明确延后并保持"未知"。
6. 人工门为界面真人确认并剥离模型自报参数（S13，已实现）；设备切换复位旧后端（B1，已实现）；断连收跟踪环（S15，已实现）；三条均补回归用例。

**M3 能交付**

1. 许可与署名完整（HYG CC BY-SA、外部数据清单、NOTICE）。
2. 打包内含星表（P2-05）；从安装包冷启动通过 M1 演示。
3. 错误码/离线/读数/截断四类诚实性用例全绿。
4. 已知限制总账每条都有状态（真验/仅自测/未验证）与复跑条件。
5. `docs/interaction-flows.md` 中落到 P0 的缺陷全部关闭；其余缺陷有归属（P1/后续）与复现步骤。
6. 文档与汇报中不存在把未验证写成已验证的表述。

### 11.2 风险（"哪条假了会怎样"）
