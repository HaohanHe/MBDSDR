### 1.2 中心频率

```c
RTLSDR_API int rtlsdr_set_center_freq(rtlsdr_dev_t *dev, uint32_t freq);
```

- 声明：`rtl-sdr.h:145`
- 实现：`librtlsdr.c:884`
- 单位：**Hz（uint32）**，例如 433.92 MHz 传 `433920000U`。
- 实际动作（`librtlsdr.c:891-897`）：
  - 若 `direct_sampling` 开启 → 走 `rtlsdr_set_if_freq()`（DDC 直采 0~28.8 MHz）。
  - 否则通过 I2C repeater 把 `freq - offs_freq` 发给 tuner 的 `set_freq()`。
  - `offs_freq` 是 offset tuning 引入的中频偏（见 §1.7）。
- 失败时 `dev->freq = 0`（`librtlsdr.c:902`）。
- 回读：`rtlsdr_get_center_freq()`，`rtl-sdr.h:153`，直接返回 `dev->freq` 缓存。

### 1.3 采样率

```c
RTLSDR_API int rtlsdr_set_sample_rate(rtlsdr_dev_t *dev, uint32_t rate);
```

- 声明：`rtl-sdr.h:266`，文档明确写出合法区间：
  - `225001 – 300000 Hz`
  - `900001 – 3200000 Hz`
  - 速率 > 2.4 MHz 时会丢采样
- 实现：`librtlsdr.c:1089`
- 真正的范围校验在 `librtlsdr.c:1100-1104`：
  ```c
  if ((samp_rate <= 225000) || (samp_rate > 3200000) ||
     ((samp_rate > 300000) && (samp_rate <= 900000))) {
      fprintf(stderr, "Invalid sample rate: %u Hz\n", samp_rate);
      return -EINVAL;
  }
  ```
  即：**必须落在 (225000, 300000] 或 (900000, 3200000]**，中间 300k~900k 是死区。
- 实际写寄存器：`rsamp_ratio = rtl_xtal * 2^22 / samp_rate`（`librtlsdr.c:1106`），
  按 2 的倍数对齐（`& 0x0ffffffc`），所以**实际采样率和请求值会有 ppm 级偏差**，
  库会打印 `Exact sample rate is: ... Hz`（`librtlsdr.c:1113`），并把真实速率存进
  `dev->rate`（`librtlsdr.c:1115`）。回读 `rtlsdr_get_sample_rate()` 返回的是这个真实值。
- rtl_433 默认采样率：`DEFAULT_SAMPLE_RATE 250000`（`rtl_433/include/rtl_433.h:13`），
  默认中心频率 `DEFAULT_FREQUENCY 433920000`（`rtl_433/include/rtl_433.h:14`）。

### 1.4 增益模式与增益值

```c
RTLSDR_API int rtlsdr_set_tuner_gain_mode(rtlsdr_dev_t *dev, int manual); // 0=auto, 1=manual
RTLSDR_API int rtlsdr_set_tuner_gain(rtlsdr_dev_t *dev, int gain);         // 单位 0.1 dB
RTLSDR_API int rtlsdr_get_tuner_gains(rtlsdr_dev_t *dev, int *gains);     // 允许列表
RTLSDR_API int rtlsdr_set_tuner_if_gain(rtlsdr_dev_t *dev, int stage, int gain);
```

- 声明：`rtl-sdr.h:253 / 216 / 200 / 243`
- `set_tuner_gain_mode` 实现：`librtlsdr.c:1073`，直接转发给 `tuner->set_gain_mode()`。
- `set_tuner_gain` 实现：`librtlsdr.c:1028`，转发给 `tuner->set_gain()`。
- **增益单位是 0.1 dB（十分之一 dB）**，文档原话在 `rtl-sdr.h:197` 和 `rtl-sdr.h:213`：
  > "In tenths of a dB, 115 means 11.5 dB."
- E4000 合法增益表（`rtl-sdr.h:206-208` 注释 + `librtlsdr.c:959-960`）：
  `-10, 15, 40, 65, 90, 115, 140, 165, 190, 215, 240, 290, 340, 420`（单位 0.1 dB，
  即 -1.0 dB ~ 42.0 dB，14 档）。
- R820T/R828D 合法增益表（`librtlsdr.c:966-969`）：
  `0, 9, 14, 27, 37, 77, 87, 125, 144, 157, 166, 197, 207, 229, 254, 280, 297, 328,
   338, 364, 372, 386, 402, 421, 434, 439, 445, 480, 496`
  ——共 **29 档**，范围 0.0 dB ~ 49.6 dB（最大 496/10 = 49.6 dB）。
- FC0012：`-99, -40, 71, 179, 192`（`librtlsdr.c:961`）。
- FC0013：23 档，`librtlsdr.c:962-964`。

rtl_433 侧的增益字符串解析在 `rtl_433/src/sdr.c:1396`：
```c
int gain = (int)(atof(gain_str) * 10); /* tenths of a dB */
```
即用户传 `-g 32.8` 会变成 328，再调用 `rtlsdr_find_tuner_gain()`（`sdr.c:448`）
**向上取整到允许表中的下一档**（`sdr.c:472-477`），超过最大档就钳到最大档。
手动模式必须先 `rtlsdr_set_tuner_gain_mode(dev, 1)`（`sdr.c:1409`），auto 模式
传 0（`sdr.c:1359`）。

### 1.5 频率校正（ppm）

```c
RTLSDR_API int rtlsdr_set_freq_correction(rtlsdr_dev_t *dev, int ppm);
```

- 声明：`rtl-sdr.h:162`
- 实现：`librtlsdr.c:915`
- 单位：**ppm（整数 parts-per-million）**，不是 Hz。
- 实际动作（`librtlsdr.c:927-935`）：
  1. `rtlsdr_set_sample_freq_correction(dev, ppm)` 改 RTL2832 的重采样比；
  2. 回读 xtal 频率写进 e4k/r82xx 私有结构；
  3. 如果当前已调过频，**自动重新 `set_center_freq`** 让新校正生效。

### 1.6 数字 AGC / 直接采样 / offset tuning

| API | 声明 | 实现 | 作用 |
|---|---|---|---|
| `rtlsdr_set_agc_mode(dev, on)` | `rtl-sdr.h:293` | `librtlsdr.c:1157` | RTL2832 内部数字 AGC（0x19 寄存器写 0x25/0x05） |
| `rtlsdr_set_direct_sampling(dev, on)` | `rtl-sdr.h:305` | `librtlsdr.c:1165` | 1=I-ADC 直采, 2=Q-ADC 直采（绕过 tuner，0~28.8 MHz） |
| `rtlsdr_set_offset_tuning(dev, on)` | `rtl-sdr.h:324` | `librtlsdr.c:1236` | 零中频 tuner 偏频，避开 DC 偏置和 1/f 噪声 |

offset tuning 关键算法（`librtlsdr.c:1252`）：
```c
dev->offs_freq = on ? ((dev->rate / 2) * 170 / 100) : 0;
```
即把 LO 偏到采样率一半的 **85%**（≈ 0.85·fs/2），再让 tuner 带宽变成
`2 * offs_freq`（`librtlsdr.c:1258`）。R820T/R828D **不支持** offset tuning
（`librtlsdr.c:1244-1246` 直接 return -2）。

### 1.7 缓冲复位与同步读

```c
RTLSDR_API int rtlsdr_reset_buffer(rtlsdr_dev_t *dev);
RTLSDR_API int rtlsdr_read_sync(rtlsdr_dev_t *dev, void *buf, int len, int *n_read);
```

- `reset_buffer`：声明 `rtl-sdr.h:336`，实现 `librtlsdr.c:1702`。
  本质是对 USB EPA 控制寄存器做一次 0x1002→0x0000 的写（`librtlsdr.c:1707-1708`），
  清空 USB 内核队列里积压的旧 URB。**换频、换采样率之后必须调一次**，否则会读到
  上次频率的陈旧数据。rtl_433 在 `sdr.c:1706` 就是这么干的。
- `read_sync`：声明 `rtl-sdr.h:338`，实现 `librtlsdr.c:1713`。
  就是一次 `libusb_bulk_transfer(devh, 0x81, buf, len, n_read, BULK_TIMEOUT)`
  （`librtlsdr.c:1718`）。
  - endpoint `0x81` = USB IN bulk endpoint 1。
  - 返回格式：**unsigned 8-bit interleaved I/Q**，即 `buf[0]=I0, buf[1]=Q0, buf[2]=I1, buf[3]=Q1...`。
  - 每个样本 2 字节，共 `len/2` 个复样本。
  - `n_read` 是实际收到的字节数（可能 < len）。
- 异步读 `rtlsdr_read_async()`：声明 `rtl-sdr.h:369`，默认 `buf_num=15`、
  `buf_len=16*32*512=262144`（见 `rtl-sdr.h:362-366` 注释和
  `rtl_433/include/rtl_433.h:17` 的 `DEFAULT_BUF_LENGTH`）。
  rtl_433 实际在 `sdr.c:553` 调用。

## 2. IQ 格式：unsigned 8-bit offset binary

这是最容易踩坑的地方。RTL2832 的 USB 输出**不是有符号 8-bit**，而是
**无符号 8-bit offset-binary**：零点在 128（工程上常说 127.4，因为 ADC 偏置略偏）。

### 2.1 rtl_433 的实际换算代码

| 函数 | 位置 | 换算 |
|---|---|---|
| `calc_squares()` 建表 | `baseband.c:25-32` | `scaled_squares[i] = (127 - i)^2` —— 注意用的是 **127** 而不是 128 |
| `envelope_detect()` | `baseband.c:36-44` | 查表法求 `I^2+Q^2`（OOK 包络） |
| `envelope_detect_nolut()` | `baseband.c:49-59` | 直接 `x = 127 - iq[2i]; y = 127 - iq[2i+1]` |
| `magnitude_est_cu8()` | `baseband.c:63-76` | `x = abs(iq[2i] - 128); y = abs(iq[2i+1] - 128)`，再用 `122*max+51*min` 近似 |
| `magnitude_true_cu8()` | `baseband.c:79-89` | `x = iq[2i] - 128; y = iq[2i+1] - 128; y_buf = sqrtf(x²+y²)*128` |
| `baseband_demod_FM()` | `baseband.c:247-248` | `x0r = *x_buf++ - 128; x0i = *x_buf++ - 128` |

注意一个细节：**LUT 包络用 127， magnitude/FM 用 128**。
这不是 bug，而是 rtl_433 故意的——`127 - i` 在 i=0 时给出 127，i=255 时给出 -128，
对称地把 ADC 的满量程映射到 ±127/±128； magnitude 分支用 `abs(x-128)` 则
把中心放在 128，两者都能工作，只是直流偏置估计差 0.5 LSB，可忽略。

### 2.2 转 float complex 的标准写法

```python
# 正确（rtl_433 等价：减 128，除以 127.5）
raw  = np.frombuffer(buf, dtype=np.uint8)          # shape (2N,)
iq   = raw.astype(np.float32) - 128.0              # 中心搬到 0
iq  /= 127.5                                        # 归一到 [-1, 1]
zc   = iq[0::2] + 1j*iq[1::2]                      # complex64
```

MBDSDR 自己的 `sdr_backend.py:1089` 读文件时就是这么做的：
```python
self._samples = np.asarray(((raw - 127.5) / 127.5).view(np.complex64).reshape(-1), ...)
```
写文件时（`sdr_backend.py:319-321`）：
```python
ui = np.clip(z.real, -1.0, 1.0) * 127.5 + 127.5
uq = np.clip(z.imag, -1.0, 1.0) * 127.5 + 127.5
```
——和 rtl_433 完全一致，**这里没问题**。

### 2.3 直流偏置（DC offset）

零中频 tuner 的 DC 偏置来自本振泄漏，在频谱中心形成一个尖峰。处理手段有三层：

1. **硬件层 offset tuning**：把 LO 偏开 0.85·fs/2（见 §1.6，`librtlsdr.c:1252`）。
   R820T 不支持，只能靠软件。
2. **库内 DC 校正**：RTL2832 自带 DC 偏移补偿寄存器（rtl_433 默认开启）。
3. **软件层去均值**：在做幅度检测前，rtl_433 **不直接做 I/Q 去直流**，而是
   对包络幅度做自适应噪声估计（见 §4），让 OOK 门限自己跟踪 DC。
   这是因为对 OOK 来说，DC 尖峰只是抬高了"底噪"，自适应低电平估计
   `ook_low_estimate`（`pulse_detect.c:328`）会把它吸收掉。

## 3. 增益控制：E4000 vs R820T，AGC vs 手动

### 3.1 E4000（Elonics E4000）

E4000 是 6 级 IF + LNA + mixer 的组合 tuner。增益表在
`librtlsdr/src/tuner_e4k.c:646-660`：
```c
static const int32_t lnagain[] = {
    -50, 0,   -25, 1,    0, 4,    25, 5,    50, 6,
    75, 7,   100, 8,   125, 9,   150, 10,  175, 11,
   200, 12,  250, 13,  300, 14,
};  // 每对是 (增益 0.1dB, 寄存器值)
```
IF 各级步进（`tuner_e4k.c:600-614`）：
- stage1: -3, 6 dB
- stage2/3: 0, 3, 6, 9 dB
- stage4: 0, 1, 2, 2 dB
- stage5/6: 3, 6, 9, 12, 15, 15, 15, 15 dB

整体范围约 **-10 dB ~ +100 dB 等效**，对外暴露给上层的 14 档在
`librtlsdr.c:959-960`（-1.0 dB 到 42.0 dB）。

### 3.2 R820T / R828D（最常见的廉价棒）

R82xx 由 LNA + Mixer + VGA 三级组成。步进表在
`librtlsdr/src/tuner_r82xx.c:966-977`：
```c
#define VGA_BASE_GAIN  -47
static const int r82xx_vga_gain_steps[]  = { 0, 26, 26, 30, 42, 35, 24, 13,
                                             14, 32, 36, 34, 35, 37, 35, 36 };
static const int r82xx_lna_gain_steps[]  = { 0, 9, 13, 40, 38, 13, 31, 22,
                                             26, 31, 26, 14, 19,  5, 35, 13 };
static const int r82xx_mixer_gain_steps[] = { 0, 5, 10, 10, 19, 9, 10, 25,
                                              17, 10,  8, 16, 13,  6, 3, -8 };
```
手动增益算法（`tuner_r82xx.c:979-1046`）：
1. 关 LNA/Mixer 自动增益（`0x05`/`0x07` 寄存器写 0x10）；
2. 把 VGA 固定在 0x08（≈16.3 dB，`tuner_r82xx.c:1003`）；
3. 从 0 开始累加 `lna_steps[++lna_idx]` 和 `mixer_steps[++mix_idx]`，
   直到 `total_gain >= 目标 gain`（`tuner_r82xx.c:1007-1017`）；
4. 把 lna_idx/mix_idx 写回 `0x05`/`0x07` 的低 4 位。

自动模式（`tuner_r82xx.c:1028-1043`）：
- 开 LNA/Mixer 自动增益（写 0x10 位）；
- VGA 固定在 0x0b（≈26.5 dB）。

对外 29 档列表见 §1.4，范围 0.0 ~ 49.6 dB，**步进非线性**（不是 0.1 dB 连续可调）。

### 3.3 AGC vs 手动的选择

| 模式 | API | 行为 |
|---|---|---|
| Tuner 自动增益 | `rtlsdr_set_tuner_gain_mode(dev, 0)` | LNA/Mixer 由 tuner 内部 AGC 环控制 |
| Tuner 手动增益 | `rtlsdr_set_tuner_gain_mode(dev, 1)` + `set_tuner_gain()` | 固定 LNA/Mixer 档位 |
| 数字 AGC（RTL2832） | `rtlsdr_set_agc_mode(dev, 1)` | 基带数字增益自动，和 tuner AGC 独立 |

rtl_433 默认：**tuner AGC 开**（不传 `-g` 时走 `sdr.c:1359`）。
做 433 MHz 遥控/传感器 OOK 接收时，AGC 会把弱信号"顶起来"，
但脉冲间隙也会被拉高，导致门限抖动——所以很多协议作者建议
**手动固定一个中等增益（例如 R820T 的 328 = 32.8 dB）**。

## 4. rtl_433 脉冲检测流水线

### 4.1 整体链路（`r_flow.c:104` push_sdr_flow）

### 4.2 幅度提取细节

默认 `use_mag_est=0`（ampest，`rtl_433.c:960`），走 `envelope_detect()`：
- 用 LUT `scaled_squares[i] = (127-i)²`（`baseband.c:31`）；
- 每样本输出 `I²+Q²`（max 32768，fs 16384，`baseband.c:55` 注释）；
- 这是**功率包络**（不是真包络），所以后面 `pulse_detect` 的电平估计
  是按"功率"校准的。

加 `-Y magest`（`rtl_433.c:965-966`）走 `magnitude_est_cu8()`：
- `x = abs(I-128), y = abs(Q-128)`；
- `mag = 122*max(x,y) + 51*min(x,y)`（`baseband.c:71`）；
- 这是 Pratt 近似 `|z| ≈ α·max + β·min`，α/β=122/51，最大误差 ~1%；
- 比 sqrt 快很多，且强调小信号（"emphasizes quiet signals"，`baseband.c:62` 注释）。

### 4.3 去直流

rtl_433 **不在 I/Q 域做去直流**。它的策略是：
- 包络/幅度本身是 `I²+Q²` 或 `|I+jQ|`，DC 尖峰会被当成"大噪声底"；
- OOK 门限自适应估计（§4.4）把这个底噪跟踪下来；
- 如果 DC 偏置严重，用户应该开 offset tuning（`-Y tune=offset`，
  `rtl_433/src/sdr.c:1633`）让 LO 偏开。

### 4.4 OOK 峰值检测状态机（`pulse_detect.c:199`）

核心常量（`pulse_detect.c:24-27`）：
```c
#define OOK_MAX_HIGH_LEVEL  DB_TO_AMP(0)     // 高电平上限 0 dB
#define OOK_MAX_LOW_LEVEL   DB_TO_AMP(-15)   // 低电平上限 -15 dB
#define OOK_EST_HIGH_RATIO  64               // 高电平估计时间常数
#define OOK_EST_LOW_RATIO   1024             // 低电平估计时间常数（很慢）
```

四个状态（`pulse_detect.c:36-41`）：
`IDLE → PULSE → GAP_START → GAP → IDLE`。

每样本处理（`pulse_detect.c:293-475`）：
1. 读 `am_n = envelope_data[data_counter]`（`pulse_detect.c:295`）；
2. 算门限：
   ```c
   ook_threshold = (ook_low_estimate + min(ook_high_estimate, OOK_MAX_HIGH_LEVEL)) / 2;
   ook_hysteresis = ook_threshold / 8;   // ±12% 滞回
   ```
   （`pulse_detect.c:300-304`）——**门限是高/低估计的中点，带 ±12% 滞回**，
   避免在门限附近抖。
3. IDLE 状态：若 `am_n > threshold + hyst` 且 lead-in 已稳定 → 进 PULSE；
   否则慢慢更新低电平估计：
   ```c
   ook_low_estimate += (am_n - ook_low_estimate) / 1024;
   ook_low_estimate += sign(am_n - ook_low_estimate);  // 定点补偿
   ook_high_estimate = ook_high_low_ratio * ook_low_estimate;  // 默认 8x
   ```
   （`pulse_detect.c:327-333`）。
4. PULSE 状态：`pulse_length++`；若 `am_n < threshold - hyst` → 脉冲结束，
   记录 `pulses->pulse[num_pulses] = pulse_length`（`pulse_detect.c:353`），
   进 GAP_START；同时慢更新高电平估计
   ```c
   ook_high_estimate += am_n/64 - ook_high_estimate/64;
   ```
   （`pulse_detect.c:362`）。
5. GAP_START：短 gap 防抖——如果 gap 还没到 `PD_MIN_PULSE_SAMPLES` 就又看到
   高电平，说明是毛刺，把脉冲长度加回去（`pulse_detect.c:380`），回 PULSE。
6. GAP：若再次 `am_n > threshold + hyst` → 记录 gap 宽度，num_pulses++，
   回 PULSE（`pulse_detect.c:425-443`）。
   若 gap 太长（`> PD_MAX_GAP_RATIO * max_pulse` 且超过最小 gap，
   或 > `PD_MAX_GAP_MS`）→ 整包结束，返回 `PULSE_DATA_OOK`
   （`pulse_detect.c:447-468`）。

### 4.5 脉冲序列输出

一个"package"返回后，`pulse_data_t` 里有：
- `pulse[]`：每个高电平持续样本数；
- `gap[]`：每个低电平持续样本数；
- `num_pulses`：脉冲个数；
- `sample_rate`：当前采样率（用来把样本数换算成 µs）；
- `ook_low_estimate / ook_high_estimate`：本次估计的噪声/信号电平；
- `fsk_f1_est / fsk_f2_est`：FSK 两个频点估计。

然后 `r_flow.c:259` 把 pulse_data 丢给所有注册的 OOK decoder，每个 decoder
按自己的协议（曼彻斯特、PWM、PPM...）去解码。

## 5. 可迁移到 MBDSDR 的点（对照自查）

对照文件：
- `mbdsdr_ai/sdr_backend.py`（RTLSDRBackend，行 463-660）
- `mbdsdr_ai/hal.py`（SoapySDR 抽象，行 65-300）
- `mbdsdr_ai/radio_control.py`（主要是 morse/音频，不涉及 RTL-SDR 控制）

### 5.1 采样率范围 ✅ 基本正确

- MBDSDR 声明：`sample_rate_range=(250000, 3200000)`（`sdr_backend.py:482`）。
- librtlsdr 实际：(225000, 300000] ∪ (900000, 3200000]（`librtlsdr.c:1100-1104`）。
- **问题**：MBDSDR 允许 250k~3.2M 连续，但 300k~900k 之间 librtlsdr 直接
  返回 -EINVAL。当前范围下限 250k 没问题，但用户如果设 500k 会失败。
- **建议**：在 `RTLSDRBackend._apply_sample_rate`（`sdr_backend.py:563`）里
  加一段校验：
  ```python
  if not ((225000 < r <= 300000) or (900000 < r <= 3200000)):
      raise ValueError(f"RTL-SDR rate {r} Hz out of valid bands")
  ```
- 另外注意 librtlsdr 会按 2²²/xtal 取整，实际速率和请求值有 ~几十 ppm 偏差，
  MBDSDR 应该在 `_reprobe`（`sdr_backend.py:583-593`）后把
  `status.sample_rate_hz` 更新成回读的真实值，而不是用户请求值。当前代码
  已经这么做了（`sdr_backend.py:588`），✅。

### 5.2 增益单位 ⚠️ 可能踩坑

- MBDSDR 接口：`set_gain(gain_db: float)`（`sdr_backend.py:160`），
  默认 `gain_db=0.0`（`sdr_backend.py:58`），`max_gain=49.6`
  （`sdr_backend.py:483`）。
- pyrtlsdr 的 `self._sdr.gain = float(gain_db)`（`sdr_backend.py:573`）——
  **pyrtlsdr 接收的是 dB（浮点），不是 0.1 dB 整数**，它内部会自己查表。
  这和 C API 的 `rtlsdr_set_tuner_gain(dev, int gain_tenths)` 单位不同。
- librtlsdr 真实档位是非线性 29 档（§3.2），传 32.8 实际可能被四舍五入到
  328 或 338。MBDSDR 当前直接把 float 透传给 pyrtlsdr，依赖 pyrtlsdr 内部
  做最近档选择——**行为和 rtl_433 的 `rtlsdr_find_tuner_gain`（向上取整，
  `sdr.c:472-477`）略有差异**，但可接受。
- **建议**：把 `max_gain` 改成 `49.6` 已经对齐 R820T 最大值；
  但 E4000 最大只到 42.0 dB（`librtlsdr.c:959-960`），如果用户插 E4000
  棒，传 49.6 会被钳到 42.0，MBDSDR 状态却显示 49.6。建议在 `_reprobe`
  里读一次 `rtlsdr_get_tuner_type` 动态调整 `device.max_gain`。

### 5.3 ppm 校正 ✅ 正确

- MBDSDR：`set_ppm(ppm)` → `self._sdr.freq_correction = ppm`
  （`sdr_backend.py:628-633`）。
- librtlsdr：`rtlsdr_set_freq_correction(dev, ppm)`（`librtlsdr.c:915`），
  单位就是 ppm，且会自动 retune。✅ 完全对齐。
- 默认 `ppm=0`（`sdr_backend.py:476`），和 rtl_433 默认 `-p 0` 一致。

### 5.4 AGC 切换 ✅ 正确

- MBDSDR：`set_agc(True)` → `self._sdr.set_agc_mode(True)`
  （`sdr_backend.py:605-610`）。
- 对应 C API `rtlsdr_set_agc_mode`（`librtlsdr.c:1157`），是 RTL2832 数字 AGC。
- **注意**：这和 tuner 前端 AGC（`rtlsdr_set_tuner_gain_mode`）是两回事。
  MBDSDR 现在只控制了数字 AGC，**没有控制 tuner gain mode**。
  当用户 `set_gain(32.8)` 时，pyrtlsdr 内部应该会自动切到 manual 模式
  （rtl_433 在 `sdr.c:1409` 就是这么做的），但 MBDSDR 自己没显式调
  `set_tuner_gain_mode`，万一 pyrtlsdr 版本行为变了会出问题。
- **建议**：在 `_apply_gain`（`sdr_backend.py:569-573`）里显式
  `self._sdr.set_manual_gain_mode(True)`，在 `set_agc(True)` 里显式
  `self._sdr.set_manual_gain_mode(False)`，对齐 rtl_433 的做法。

### 5.5 IQ 格式与 DC 偏置 ✅ 正确

- MBDSDR 写文件：`*127.5 + 127.5`（`sdr_backend.py:320-321`）；
- MBDSDR 读文件：`(raw - 127.5)/127.5`（`sdr_backend.py:1089`）；
- rtl_433：`x - 128`（`baseband.c:67,83,247`）或 `127 - i`（`baseband.c:31,53`）。
- 中心差 0.5 LSB，对 SDR 应用可忽略。✅

### 5.6 缺的功能点

对照 rtl_433 支持但 MBDSDR 还没暴露的：
1. **`rtlsdr_reset_buffer()`**（`librtlsdr.c:1702`）：换频/换采样率后必须调，
   否则会读到陈旧 URB。MBDSDR 的 `_apply_center_freq`（`sdr_backend.py:560`）
   只设了 `center_freq`，没 reset buffer。**建议加一行 `self._sdr.reset_buffer()`**。
2. **offset tuning**（`librtlsdr.c:1236`）：零中频 DC 偏置的硬件解法，
   R820T 不支持但 E4000 支持。MBDSDR 可以加个 `set_offset_tuning(bool)`。
3. **direct sampling**（`librtlsdr.c:1165`）：绕过 tuner 直接采 0~28.8 MHz，
   适合 HF 接收。MBDSDR 目前没暴露。
4. **bias tee**（`librtlsdr.c:2054`）：MBDSDR 已经有 `set_bias_tee`
   （`sdr_backend.py:656-660`），✅。
5. **脉冲检测流水线**：MBDSDR 目前走通用 demod（`analog_demod.py`、`demod.py`），
   没有 rtl_433 那套自适应 OOK 门限 + 滞回 + 状态机。如果要做 433 MHz
   遥控解码，建议把 `pulse_detect.c:199` 的状态机直译到 Python/numpy：
   - 门限 `(low+high)/2`，滞回 `±12.5%`；
   - 低电平估计时间常数 1024，高电平 64；
   - 最小脉冲样本数 `PD_MIN_PULSE_SAMPLES`，最大 gap 比例
     `PD_MAX_GAP_RATIO`。

## 7. 一句话总结

RTL-SDR 的控制面极简：**Hz 调频率、整数 ppm 校正、0.1 dB 调增益、
0/1 切 AGC、bulk endpoint 0x81 读 unsigned 8-bit interleaved I/Q（中心 128）**。
rtl_433 的聪明之处不在射频控制，而在**基带后处理**：
用 `122*max+51*min` 快速包络 + 一阶 IIR 低通 + 自适应中点门限（±12% 滞回）
+ 四状态脉冲机，把 250 kS/s 的裸 IQ 直接变成"脉冲宽度序列"，再喂给
上百个协议 decoder。MBDSDR 当前的 `sdr_backend.py` 在 IQ 格式和 ppm 上
已经对齐，主要差距在**换频后没 reset_buffer、没显式切 tuner gain mode、
采样率范围没区分 librtlsdr 的两段合法区间**——这三点是下次迭代应该补的。
