## 1. 候选 A：载波恢复 PLL

**现状痛点**：本振固定 1500 Hz（`cdcss.cpp:125`）。真实 DCS 发射机的键控载波并不严格等于 1500 Hz（常见 1500±几十 Hz，且晶振/解调残差会漂移）。固定本振下，I 支路积分会随本振与实际载波的频差产生**拍频**——频差越大，半个位周期内 I 积分的幅度被衰减到 cos(Δφ)，超过约半位周期内 π/4 累积就会把符号判反。当前合成测试把载波精确设成 1500 Hz，所以测不出这个弱点。

**方案设计（接口/数据流）**
- 保留同一 `process(const float*,int)` 入口；内部把单路 I 积分升级为**复数 NCO 混频**：同时算 `I += x·cos(φ)`、`Q += x·sin(φ)`（或反之，与现 sin 约定一致）。
- 在每个半位 strobe 时刻，用半位内的 (ΣI, ΣQ) 估计相位误差 `e = ΣI·(−ΣQ) − ...`（Costas / 极性判决鉴相：极性 D = sign(ΣI)，`e = D·ΣQ`），经比例-积分环路滤波后**微调 `dPhase_`**（而不是固定 2π·1500/sr）。
- 收敛后 `φ` 锁住实际键控载波，`ΣI` 恒为大正负、`ΣQ≈0`；位判决仍取 `ΣI` 符号。
- 新增私有状态：`qAcc_`、环路滤波器状态（`pIState_`）、环路带宽常量（TU 内 constexpr，不碰 tokens.h）。`configure()` 里仍以 1500 Hz 为 `dPhase_` 初值（锁的起点）。

**测试影响**：合成测试用 1500 Hz 键控——PLL 从 1500 Hz 起锁 1500 Hz，**稳态行为不变，既有 13 个单测 + 全链 e2e 应继续绿**。但要**新增**一个"载波偏 50–100 Hz 仍能锁"的确定性用例才能自证 PLL 价值（否则 PLL 只是白加复杂度）。

**风险**
- 环路带宽选小→锁得慢（拉起延迟吃掉 warmup）；选大→在 134.4 bps 位跳变处过冲、误锁。
-  Manchester 跳变是相位反转点，极性 Costas 在跳变瞬间鉴相会抖——需要半个位周期的积分窗自然平均掉，风险中等。
- 引入额外收敛期：`codePresent()` 在未锁定期必须诚实读 false（不能假装锁上）。

**工作量**：M（混频升级 + 环路滤波 + 收敛态机 + 偏频新用例，约 60–90 行 + 测试）。
**建议**：**缓做**。当前合成与受控链路下固定本振已全绿；PLL 的真实价值要在"实际电台接收、载波有漂移"时才显现。等有真实 RF/IQ 录波样本可回归时再上（与真实接收联调轮合并）。

## 2. 候选 B：位钟早-晚纠错（early-late gate）

**现状痛点**：位钟靠 `countdown_=halfBitPeriod_` 自由运行（`cdcss.cpp:156,186`）。合成端与解码器共用同一分数网格所以严丝合缝；但真实链路里，位钟会因采样率不匹配/通道群延迟而**缓慢漂移**，几十位后采样点从中位滑到边沿，Manchester 判决裕度归零。

**方案设计**
- 把单 strobe（半位中心采样）扩成**早-晚双采样**：在每个半位窗内取两个相邻子积分（早点 = 窗前 1/4，晚点 = 窗后 1/4），比较两者 |I|。
- 若早点能量 > 晚点 → 位钟**偏晚**，把 `countdown_` 的下一次触发**提前**一点；反之延后。误差经小系数低通后微调 `countdown_`（不改变 `halfBitPeriod_` 本身，只调相位偏移）。
- 仍以中心采样（或早晚平均）作为位判决值，保持 Manchester 配对逻辑不变。

**测试影响**：现有 1500 Hz 对齐合成测试应仍绿（早晚能量对称 → 校正量≈0）。需新增"人为给半位网格加固定偏移、验证早-晚把采样拉回中心"的用例。

**风险**
- 需要更细的积分分窗（把半位拆成 2–3 段累加），改动 `process()` 内层循环，要小心不破坏 Golay 码字边界（`bitsInWord_` 的推进仍只能由半位 strobe 驱动，早-晚只调相位不调速）。
- 在低 SNR / 噪声下早晚能量差被噪声淹没 → 校正抖动，需死区/门限。

**工作量**：M（内层循环分窗 + 校正滤波 + 边界保持 + 新用例）。
**建议**：**缓做**，且**优先于 PLL**。它解决的是"长期漂移导致判错位"——这是真实接收下最常见的失效模式，且与载波是否锁正交。建议排在 PLL 之前的独立一轮，或与 PLL 同轮一起上（二者都在 `process()` 内层，合并改一次更省）。

## 3. 候选 C：Golay 纠错权重 3（t=3 全纠错）

**现状痛点**：查表只建权重 0..2（`cdcss.cpp:60-82`）。(23,12,7) 最小距 7，理论纠错半径 t=3；当前 3 比特错误的字被判 uncorrectable → miss。

**数学事实（干净室核算）**：2^11=2048 个综合征。权重≤3 错误图样数 = 1 + C(23,1) + C(23,2) + C(23,3) = 1+23+253+1771 = **2048，恰好填满全部陪集**。且：两错误图样 e_a、e_b 同综合征 ⟺ e_a⊕e_b 是码字；最轻码字重 7，而 ≤3⊕≤3 的重 ≤6，**永不等于码字**——故权重 1/2/3 的综合征两两不撞、彼此不覆盖。即扩展为权重 3 是一个**无冲突的完整陪集主代表表**。

**方案设计**：在 `golay23Table()` 建表循环里再加一层 `e2<e3` 三元循环（保持"先到先占"插入，且上面已证不撞既有 ≤2 项）。`golay23Decode` 逻辑不变。

**关键风险（为什么不是"零风险顺手做"）**：
- 现状：综合征查不到 → 返回 false → onWordComplete 记一次 **miss**（噪声毛刺被诚实丢弃）。
- 扩展后：**每个综合征都能映射到某个权重≤3 图样**，`golay23Decode` 几乎不再返回 false。意味着一段纯噪声里，每 23 位都会被"纠"成某个 12 位地址——噪声从此不断产出**看似合法的假码**，喂给 latch。这**直接改变 false-positive 语义**：本应由 miss 吸收的噪声，现在变成候选码，需要靠"连续 3 个相同字才 latch"去挡。在强噪声下误 latch 概率上升。
- 因此 t=3 不是单纯"多纠 1 bit"，而是要配套想清楚：**未命中 configuredCode_ 的解码结果要不要进 miss 计数**（现状 onWordComplete 已如此），以及是否要给"t=3 纠正"降权（例如纠正到 t=3 的字不立即算命中，需更多连续命中）。这是一个需要单独设计与噪声回归的决策。

**测试影响**：需新增 3-bit 翻转纠正用例；并**新增强噪声回归**证明误 latch 不劣化。

**工作量**：S（建表加层约 5 行），但**配套语义调整 + 噪声回归 = M**。
**建议**：**缓做，单开一轮**。表扩展本身极便宜，但它触碰 latch 的 false-positive 语义，必须连同噪声鲁棒性测试一起上，不能"顺手"。

## 5. 建议排期（不本轮）

- **下一个独立 DSP 增强轮**：合并实现 B（早-晚）+ A（PLL）——二者都在 `process()` 内层，一次改完，共享"真实载波/位钟漂移"新用例矩阵（合成端人为加频差 + 位网格偏移）。
- **再一轮**：C（Golay t=3），配套"t=3 纠正降权 latch"语义决策 + 强噪声误 latch 回归。
- **前提条件**：以上三者的真实验证都依赖"非理想合成"（频差/位偏/强噪声）用例；在只有理想对齐合成样本时，上增强只会加复杂度而测不出收益。故建议等有真实 RF/IQ 录波或非理想注入用例后再做。

## 6. 诚实说明

- 本轮**未改任何 .cpp/.h**，只落本文档。
- 三候选均判定为 M（C 的建表虽 S，但语义调整使其整体 M），**无一项满足"S 且零风险"**，故不顺手实现——与"默认只落文档"一致。
- t=3 的"2048 恰好填满、综合征不撞"为干净室 GF(2) 核算结论，实现时仍需用穷举 2048 综合征自证表的双射性质（2^11 个 key、无重复值映射冲突）。
