## 1. Mode S Preamble 检测

### 1.1 物理形状
Preamble 长 8 µs，由 4 个 0.5 µs 脉冲组成，位置在
**0.0 / 1.0 / 3.5 / 4.5 µs**（相对 preamble 起点）。
数据从第 8 µs 开始。在 2 MHz 采样下，每 µs = 2 样本，
所以 preamble 占 mag 缓冲 `m[j .. j+15]` 共 16 个样本。

### 1.2 幅度流从哪来
RTL-SDR 送上来的是 interleaved unsigned 8-bit IQ（UC8），
先做 `convert_uc8` → `starch_magnitude_uc8`，把 I/Q 包络算成 uint16 幅度：

- `sdr_rtlsdr.c:283`  `RTLSDR.converter = init_converter(INPUT_UC8, ...)`
- `convert.c:22-38`  `convert_uc8()` 调 `starch_magnitude_uc8(in, mag_data, nsamples, ...)`
- `sdr_rtlsdr.c:365`  每回调里 `RTLSDR.converter(buf, &outbuf->data[overlap], samples_read, ...)`

也就是说，preamble 检测吃的不是复平面 IQ，而是 **|I+jQ| 的 uint16 包络流**。

### 1.3 滑动窗口找 preamble（demod_2400.c）
主循环 `demodulate2400()` 对每个样本 `j` 取 `preamble = &m[j]`：

- `demod_2400.c:135`  `uint16_t *preamble = &m[j];`
- `demod_2400.c:155`  粗筛：`preamble[0] < preamble[1] && preamble[12] > preamble[13]`
  （必须在样本 0→1 上升、样本 12→13 下降，对应第 1 个脉冲上升沿和第 4 个脉冲后沿）。
- `demod_2400.c:158-201`  五路“相位模板”匹配。因为 RTC 采样时钟不一定和
  发射机同相，脉冲峰可能落在相邻样本上。五套模式分别匹配峰在：
  - phase 3：峰样本 `1, 3, 9, 11-12`（`demod_2400.c:158-165`）
  - phase 4：峰样本 `1, 3, 9, 12`（`demod_2400.c:166-173`）
  - phase 5：峰样本 `1, 3-4, 9-10, 12`（`demod_2400.c:174-181`）
  - phase 6：峰样本 `1, 4, 10, 12`（`demod_2400.c:182-189`）
  - phase 7：峰样本 `1-2, 4, 10, 12`（`demod_2400.c:190-197`）

  对应到 µs：样本 1≈0.5µs 脉冲、样本 3≈1.5µs 脉冲、样本 9≈4.5µs 脉冲、
  样本 11-12≈5.5µs？——注意 dump1090 的注释 `demod_2400.c:146-151`
  里 sample# 编号是从 0 开始，相位偏移导致脉冲跨两个样本，
  本质就是 0/1/3.5/4.5 µs 四个峰在 2 MHz 下的 5 种亚采样相位。

- `demod_2400.c:163-173`  对命中的模板算 `high`（四峰平均）和
  `base_signal`（峰幅度和）/ `base_noise`（静默样本幅度和）。
- `demod_2400.c:204`  SNR 门限：`if (base_signal * 2 < 3 * base_noise) continue;`
  ≈ 3.5 dB（与 `dump1090.h:98` 的 4 dB 一致）。
- `demod_2400.c:208-218`  静默区间必须真的安静：样本 5,6,7,8,14,15,16,17,18
  都不得 ≥ high，否则认为有旁瓣干扰，丢弃。
- `demod_2400.c:221`  `Modes.stats_current.demod_preambles++` 计数。

### 1.4 位判决
preamble 命中后，`demod_2400.c:223` 再对 try_phase=4..8 五种相位各解一次，
用 `scoreModesMessage()` 打分（CRC+对称位）选最优。数据起始点
`pPtr = &m[j+19] + try_phase/5`（`demod_2400.c:230`），
即 preamble 起点 j 之后第 19 个样本起开始读数据位。
每比特 2 样本，PPM：前半样本能量 > 后半 → bit=1，否则 0。

## 2. DF 类型与报文长度

### 2.1 长度判别
- `mode_s.c:77-79`
  ```c
  int modesMessageLenByType(int type) {
      return (type & 0x10) ? MODES_LONG_MSG_BITS : MODES_SHORT_MSG_BITS;
  }
  ```
  即 **DF≥16 → 112 bit（14 字节）；DF≤15 → 56 bit（7 字节）**。
  DF 占首字节高 5 bit：`df = msg[0] >> 3`（见 `demod_2400.c:320`）。

### 2.2 各常用 DF
| DF | 名字 | 长度 | 关键说明 |
|----|------|------|----------|
| 0  | short air-air surveillance | 56 | Address/Parity |
| 4  | surveillance, altitude reply | 56 | 带 AC 高度码 |
| 5  | surveillance, identity reply | 56 | 带 ID 4096 应答机码 |
| 11 | All-call reply | 56 | Parity/Interrogator，AA 地址明文 |
| 16 | long air-air surveillance | 112 | Address/Parity |
| 17 | Extended Squitter (ADS-B) | 112 | II=0，CRC 即校验和 |
| 18 | Extended Squitter / non-TS | 112 | 同 DF17，但带 NT 过滤 |
| 20 | Comm-B altitude reply | 112 | Address/Parity |
| 21 | Comm-B identity reply | 112 | Address/Parity |

源码位置：
- `mode_s.c:556-619`  switch(msgtype) 分支。
- `mode_s.c:568-577`  DF11 分支：`mm->IID = mm->crc & 0x7f;`（低 7 bit 是 IID）。
- `mode_s.c:579-585`  DF17/18：`mm->source = SOURCE_ADSB; reliable = (correctedbits==0)`。
- `mode_s.c:587-597`  DF20/21：`mm->addr = mm->crc; reliable=0`。

### 2.3 字段布局（DF17 长帧 112 bit）
- bit 1-5   : DF（=17）
- bit 6-8   : CA（能力）— `mode_s.c:641-659`
- bit 9-32  : ICAO AA 地址（24 bit 明文）— `mode_s.c:624-626`
  `mm->AA = mm->addr = getbits(msg, 9, 32);`
- bit 33-39 : ME 第 0 字节（TC 高 5 bit + ST）— `mode_s.c:1041` 附近
- bit 40-87 : ME 剩余 6 字节（呼号 / CPR / 速度等）
- bit 89-112: CRC-24 校验和（3 字节）

DF11 短帧：bit 1-5=DF(11)，bit 6-8=CA，bit 9-32=ICAO，bit 33-56=CRC。

## 3. CRC-24 真实实现（crc.c）

### 3.1 生成多项式（重要！纠正任务里的 0xFFFA04）
- `crc.c:28`
  ```c
  #define MODES_GENERATOR_POLY 0xfff409U
  ```
  **多项式是 `0xFFF409`，不是 `0xFFFA04`。**
  （0xFFFA04 是网上某些中文博客写错的；源码里白纸黑字 0xfff409U。）
  省略最高位 x^24，余数 24 bit。

### 3.2 查表 CRC
- `crc.c:44-55`  预生成 `crc_table[256]`：
  对每个字节 i，初值 `i<<16`，左移 8 次，MSB=1 则异或 0xfff409。
- `crc.c:65-81`  `modesChecksum(message, bits)`：
  ```c
  rem = 0;
  for (i = 0; i < n-3; ++i)
      rem = (rem<<8) ^ crc_table[ message[i] ^ ((rem&0xff0000)>>16) ];
  rem = rem ^ (msg[n-3]<<16) ^ (msg[n-2]<<8) ^ msg[n-1];
  ```
  注意：前 `n-3` 字节走查表，**最后 3 字节（CRC 域）直接异或进去**，
  所以对完整 112 bit 报文调用 `modesChecksum`，合法报文返回的不是 CRC 本身，
  而是 **syndrome（陪集）**：合法时 syndrome==0。

### 3.3 残差/纠错表
- `crc.c:58-62`  预计算 `single_bit_syndrome[112]`：每 bit 单独翻 1 次算 syndrome。
- `crc.c:182-352`  `prepareErrorTable()` 枚举 1~2 bit 错误组合，
  建 syndrome→错误位图的二分查找表；`crc.c:376-377`
  对短/长报文各建一张表，max_correct=2, max_detect=4。
- `crc.c:386-405`  `modesChecksumDiagnose(syndrome, bitlen)` 二分查表。
- `crc.c:409-418`  `modesChecksumFix()` 把错误位翻回来。

### 3.4 地址反推（Address/Parity vs Parity/Interrogator）
这是 Mode S 最容易踩坑的地方：

- **DF0/4/5/16/20/21 用 Address/Parity**：发送方把自己的 24-bit ICAO
  地址 XOR 到 CRC 上发出来。接收机算 syndrome = CRC(全帧)，
  **这个 syndrome 本身就是 ICAO 地址**（因为发送方 syndrome 本来应是 0，
  被 XOR 了地址）。
  - `mode_s.c:564`   `mm->addr = mm->crc;`（DF0/4/5/16）
  - `mode_s.c:595`   `mm->addr = mm->crc;`（DF20/21）
  - `mode_s.c:612`   `mm->addr = mm->crc;`（DF24-31 ELM）

- **DF17/DF18 用 Parity/Interrogator，但 II=0**：发送方不 XOR 地址，
  syndrome==0 即代表 CRC 正确；ICAO 地址在明文 AA 域（bit 9-32）。
  - `mode_s.c:624-626` `mm->AA = mm->addr = getbits(msg,9,32);`

- **DF11 用 Parity/Interrogator，IID 可能非 0**：上行询问器 ID
  被 XOR 进 CRC 的低 7 bit。所以高 17 bit syndrome 仍可用来纠错，
  但低 7 bit 是 IID，不是地址。
  - `mode_s.c:574` `mm->IID = mm->crc & 0x7f;`
  - DF11 的 ICAO 地址同样在明文 AA 域（bit 9-32），不是从 CRC 反推。

> 关键结论：**DF11/DF17/DF18 的 ICAO 地址都在明文 bit 9-32，
> 不是 CRC 反推；只有 DF0/4/5/16/20/21 这种 Address/Parity 报文，
> ICAO 才等于 syndrome。**

## 5. 位置 / 高度编码

### 5.1 高度码 AC13（DF4/DF20 等 Comm-B）
- `mode_s.c:122-149` `decodeAC13Field()`：
  - bit 7（0x0040）= M 位：1=米制，0=英尺。
  - bit 5（0x00010）= Q 位：1=25 ft 二进制；0=Gillham Mode C。
  - Q=1 时：`n = ((AC13&0x1F80)>>2) | ((AC13&0x20)>>1) | (AC13&0xF)`，
    高度 = `n*25 - 1000`（`mode_s.c:130-134`）。
  - Q=0 时走 Gillham 译码 `decodeID13Field()` → `modeAToModeC()`，
    高度 = `100*n`（`mode_s.c:137-142`）。

### 5.2 高度码 AC12（DF17 ADS-B）
- `mode_s.c:156-177` `decodeAC12Field()`：
  - Q 位在 bit 4（0x10）。
  - Q=1：`n = ((AC12&0x0FE0)>>1) | (AC12&0xF)`，高度 = `n*25 - 1000`
    （`mode_s.c:162-165`）。
  - Q=0：插 M=0 凑成 13 bit Gillham（`mode_s.c:168-170`）。
- 在 ME 区里取字段：`mode_s.c:1041`
  `unsigned AC12Field = getbits(me, 9, 20);`
  即 ME 字节 1 的 bit1 到 ME 字节 2 的 bit4 共 12 bit。

  （`adsb_lite.py:322-325`），聚簇后 ±phase_search 样本对齐，
  思路更接近 dump1090，但缺那 5 套峰位置模板；
  **建议把 `demod_2400.c:158-201` 的 5 套相位峰比较条件直接翻译成 Python**，
  特别是“静默样本不得 ≥ high”那条，能砍掉大量假 preamble。

### 6.4 DF 解析与地址提取（最关键的 bug）
- dump1090 规则（见第 3.4 节）：
  - DF17/18：地址 = 明文 AA bit 9-32，CRC==0 才可信（`mode_s.c:624-626`）。
  - DF11：地址 = 明文 AA bit 9-32，低 7 bit syndrome 是 IID（`mode_s.c:574`）。
  - DF20/21：地址 = syndrome 本身（Address/Parity）（`mode_s.c:595`）。
- adsb.py:230-231  `df = raw[0]>>3; icao = raw[1:4]`：
  对 DF17 正确；但它**完全没处理 DF11/DF20/DF21 的 CRC 语义差异**，
  只要 `crc_ok` 就硬取 raw[1:4]，对 DF20/21 会把明文域当地址读错。
- **adsb_lite.py:274-285 的分支需要逐行核对**：
  - `adsb_lite.py:274-276` DF20/21：`icao = crc_rem; crc_ok=True`
    ✓ 符合 Address/Parity 语义，和 `mode_s.c:595` 一致。
  - `adsb_lite.py:278-280` DF11：
    ```python
    icao = crc_rem & 0xFFFFFF80  # 高17bit为地址
    ```
    **这是错的。** dump1090 `mode_s.c:574` 只把低 7 bit 当 IID，
    **并没有说高 17 bit 是地址**；DF11 的 ICAO 在明文 AA 域 bit 9-32
    （`mode_s.c:624-626` 对 DF11 也执行 `mm->AA = getbits(msg,9,32)`）。
    正确做法应该是：DF11 地址 = `bits[8:32]`，syndrome 高 17 bit
    只用来做纠错参考（且必须 ==0 才可信），不要拿来当地址。
  - `adsb_lite.py:281-285` 否则（含 DF17/18）：`icao = bits[8:32]` ✓ 正确。
- 长度判定：adsb_lite.py:305-308 `expected_len_for_df()` 把
  DF0/4/5/11 当短帧、其余长帧，与 `mode_s.c:77-79` 的 `type&0x10` 规则一致 ✓。

### 6.5 高度解码
- adsb.py / adsb_lite.py **都没实现 AC12 高度解码**
  （adsb_lite.py:11 注释自承“CPR 后续”）。要补就按
  `mode_s.c:156-177`：取 ME bit 9-20 得 12 bit，Q 位在 bit 4（0x10），
  Q=1 时 `alt = (((v&0x0FE0)>>1) | (v&0xF))*25 - 1000`。

### 6.6 CPR
- adsb_lite.py:11 标注 `needs_cpr` 但未解算。要补就移植
  `cpr.c:162-205` 的 `decodeCPRairborne()`，NL 表直接照抄
  `cpr.c:77-138` 那张 if-else 链，不要用近似公式。

### 6.7 IQ→幅度
- dump1090 用 `convert_uc8 → starch_magnitude_uc8`（`convert.c:34`）
  算的是 **|I+jQ|（线性幅度）**，不是功率。
- adsb.py:207 `env = np.abs(iq)**2` 用的是**功率**；
  adsb_lite.py:321 `amp = np.abs(iq)` 用幅度。
  两者都能跑，但跨实现比较门限时要注意平方/开方差一倍 SNR 余量。
  建议 MBDSDR 统一用 `np.abs(iq)`（线性幅度），和 dump1090 一致。

## 8. 一句话总结
dump1090 的核心链路是：
UC8 IQ → `starch_magnitude_uc8` 变 uint16 包络 →
滑动 16 样本窗用五套相位峰模板找 preamble（+静默样本/SNR 双重门限）→
5 相位 PPM 切片 → 按 `DF&0x10` 决定 56/112 bit →
CRC-24(0xFFF409) 查 syndrome 表纠错 →
DF17/18 读明文 AA 地址、DF20/21 用 syndrome 当地址、DF11 低 7 bit 是 IID →
ME 区按 TC 解呼号（ais_charset）/ 高度（Q bit 25ft）/ CPR（odd+even 配对 + NL 表）。
MBDSDR 两个 Python 文件里，adsb.py 的 CRC/字符表/preamble 思路基本对，
adsb_lite.py 的 DF11 地址提取错把 syndrome 当地址，必须改成读明文 AA 域；
另外 adsb_lite.py 的 `_ADSB_CHAR` 是截断占位版，要换成完整表。
