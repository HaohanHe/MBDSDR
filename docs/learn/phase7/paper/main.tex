\begin{abstract}
We present MBDSDR, a full-stack AI-defined software-defined radio (SDR)
reference platform that couples a C++ real-time receive chain, a Flutter
mobile client, a Python signal-processing kernel, and an OpenAI-compatible
function-calling tool layer exposing every radio operation as an
agent-callable tool. This letter focuses on the reproducible experimental
backbone: a fixed-seed Monte-Carlo runner with Wilson-score 95\% confidence
intervals, an Eb/N0--in-band-SNR calibration convention, and per-run
manifests locking script, seed, data-origin, parameters, sample count, git
SHA and UTC timestamp. [SYNC: ten synthetic experiments, $\approx$10.4k
trials; BPSK sample-rate invariance 0.595--0.705 at fixed Eb/N0; residual
$\approx$10\,Hz Doppler collapses uncompensated decoding to 6.5\% while
known-frequency restoration holds $\approx$0.94; KNN-AMR 0.96--1.00 vs.\
classical rules 0.67--1.00 at $\ge$10\,dB; local tool pipeline handles
400 mixed calls at 1.000 graceful rate. LLM-agent arm = PENDING\_ONLINE\_RUN.]
\end{abstract}

\section{Introduction}
%% SYNC: main.md §I.  Two problems + Contributions (i)--(iv).
Software-defined radio (SDR) has moved modulation, filtering and decoding into
software, but mainstream SDR tooling~\cite{gnuradio_project,sdrpp_project,satdump_project}
still requires manual, expert-driven configuration. Large language models (LLMs)
with tool-calling now make it plausible to drive a radio by natural language,
yet prior AI-SDR work largely wraps existing GUI software rather than exposing a
deterministic, reproducible measurement backbone.
\begin{itemize}
  \item Layered stack; every SDR op registered as an OpenAI function-calling
        tool~\cite{openai_function_calling}.
  \item Fixed-seed Monte-Carlo library (\texttt{experiments/common/}) with Wilson
        95\% CIs~\cite{wilson1927}, explicit Eb/N0 calibration, per-run manifests.
  \item Ten synthetic experiments, each labelled with origin / $N$ / UTC date.
  \item Honest separation: deterministic local tool pipeline (measured) vs.\ online-LLM decision layer (reported as pending).
\end{itemize}

\section{System Design}
%% SYNC: main.md §II.  Four layers + experiment library.
The C++ real-time chain records standard \texttt{.sigmf-data} /
\texttt{.sigmf-meta} files under the open SigMF recording
metadata format~\cite{sigmf_spec}. The Python kernel reuses modems and decoders
(AX.25/AFSK, ADS-B Mode-S, coherent BPSK, KNN-AMR) unchanged by the experiments,
and its orbit-determination code builds on the SGP4/SDP4 element-propagation
model~\cite{hoots1980spacetrack,vallado2006revisiting}.

\section{Related Work}
%% SYNC: main.md §V.  GNU Radio / SDR++ / SatDump; LLM-tool/MCP prototypes
%%       (interactive control, not a measurement backbone); O-RAN/6G xApp.

\emph{SDR frameworks.}  Open-source SDR software such as GNU
Radio~\cite{gnuradio_project}, SDR++~\cite{sdrpp_project}, and
SatDump~\cite{satdump_project} provides powerful fixed-function receivers but
requires manual, expert-driven configuration.

\emph{LLM tool-calling and radio agents.}  Modern chat-completion APIs expose
function-calling~\cite{openai_function_calling}, and open protocols such as the
Model Context Protocol~\cite{mcp_spec} connect LLMs to external tools. The
closest LLM-driven radio systems we located are preprints on autonomous
multi-agent RF signal generation~\cite{radiomaster2026} and agentic
observability/control of Open-RAN~\cite{mxai2025}; neither is confirmed
peer-reviewed, and both target signal generation or RAN control rather than an
open, reproducible SDR measurement backbone.

\emph{O-RAN / 6G RAN intelligence.}  Near-RT RIC and xApp
surveys~\cite{polese2023understanding} apply AI to radio-resource allocation,
not to open, reproducible SDR experimentation.

\emph{Foundations reused here.}  Recordings follow the SigMF metadata
standard~\cite{sigmf_spec}; orbit propagation uses SGP4/SDP4 as originally
specified by Hoots and Roehrich~\cite{hoots1980spacetrack} and as revisited by
Vallado et al.~\cite{vallado2006revisiting}; and all binomial success intervals
use the Wilson score interval~\cite{wilson1927}.

This work differs by (a) treating every radio operation as a versioned,
schema'd tool, and (b) shipping a fixed-seed, CI-runnable measurement library
that reports CIs, data-origin, and per-run manifests so that ``AI runs the
radio'' claims are auditable.
