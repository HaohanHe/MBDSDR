## 0. 验收前准备（每次必做）

1. 确认接好 RTL-SDR（RTL2832U + R820T/R828D），`lsusb | grep -i rtl` 能看到设备。
2. 在 `cpp/build` 用 offscreen 环境外的真实显示环境重新全量构建并启动主程序：
   ```bash
   cd cpp/build
   export LD_LIBRARY_PATH=/home/user/Qt/6.8.2/gcc_64/lib:/home/user/.local/lib
   ./mbdsdr          # 真实桌面环境，不要设 QT_QPA_PLATFORM=offscreen
   ```
3. 源选择切到真实 RTL-SDR（非「测试信号」）。界面顶部信息栏应显示真实 `Fs`/`F0`，
   **不应**出现「测试信号（非硬件） · NOT HARDWARE」横幅。
4. 打开日志输出（或观察 stderr/qInfo），下列多项判定需要看日志里的 `[RtlSdrSource]` / AGC / 色板行。

## 1. Tune 重试（PLL 写回防御）— ✅ 已落地

**代码位置**：`src/dsp/rtl_sdr_source.cpp:217-251`（`pushCenterFreq`）；重试次数常量
`src/dsp/rtl_sdr_ops.h:62` `kRtlMaxTuneAttempts = 5`。

**机制**：每次写中心频率后回读硬件实际停放频率，最多写 5 次，**只有回读值==目标值**才判定收敛；
写返回 ok 但 PLL 停在别处也继续重试；5 次仍不对就大声告警并返回 false，绝不「假装调好」。

**验证方法**：
1. 启动后，在刻度条/输入框把频率连续调到几个不同频点（含 145 MHz、433 MHz 等易失锁频点）。
2. 观察日志：
   - 一次成功：无特别提示。
   - 需重试才收敛：应出现
     `[RtlSdrSource] tune to <Hz> converged after <N> retries`。
   - 始终不收敛：应出现
     `[RtlSdrSource] tune to <Hz> FAILED after 5 attempts (last rc=.. readback=.. Hz); request kept but hardware is NOT at the requested frequency`。

**预期输出**：拨号频率与实际回读一致；UI 不谎报已调谐。

**判定标准**：
- 通过：连续调 5 个频点后，界面显示频率与日志回读一致；若某次难锁，日志明确打印 `converged after N retries` 或 `FAILED`，而**不是**静默成功。
- 不通过：调谐后 UI 显示在目标频点，但收到的信号明显偏（读到回读≠目标却没有任何告警）。

## 2. 带宽自动（set_tuner_bandwidth(0)）— ✅ 已落地

**代码位置**：`src/dsp/rtl_sdr_source.cpp:290` `set_tuner_bandwidth(dev, 0)`。

**机制**：显式把 tuner 带宽设为 0，交给驱动按当前采样率自动选择匹配带宽（对齐 SDR++ main.cpp:310），
避免依赖 librtlsdr 隐式默认、将来换后端时漂移。

**验证方法**：
1. 分别用两个采样率启动：约 2.4 MS/s 与约 1.024 MS/s（界面 FFT/采样率设置处切换后重启接收）。
2. 观察频谱两侧的模拟带边缘（噪声 floor 滚降到 0 的位置）。
3. 看日志 `set_tuner_bandwidth` 的 `checkRtl` 返回码。

**预期输出**：每个采样率下，频谱有效带宽与采样率相称；两侧滚降自然，不出现「中间亮、两边一大段死黑」。

**判定标准**：
- 通过：2.4M 时可见带宽接近 2.4M、1.024M 时收窄到约 1M；日志 `set_tuner_bandwidth` rc=0（个别老 tuner 返回非致命值可接受，但需有记录）。
- 不通过：任意采样率下两侧都有一大段与采样率不成比例的死黑/空带，或带宽明显没跟着采样率走。

## 3. 链内 AGC 听感 — 🟡 在途（P2）

**代码位置**：`src/dsp/agc.h` `ComplexCarrierAgc`（复数基带、包络检波**之前**跑在 AM 链路上）；
`Agc::setCarrierAgc(bool)` 切换工作点与攻击速度。对齐 SDR++ am.h carrier AGC 机制（干净室）。

**机制**：对复数 IQ 先做幅度归一化，强载波不压垮包络检波、弱载波从噪声里抬出来，同时不破坏调制包络。

**前置**：本项需 P2 批次合并、重新构建后再做；构建未过则整项标记「未测」。

**验证方法**：
1. 调到一个真实 AM 广播（本地中波/短波，或 98.5 MHz 附近 FM 邻近的 AM 环境）。
2. 打开链内 AGC，再关掉，反复对比听感；再切到一个很弱的台。

**预期输出**：强台不刺耳/不削波失真；弱台能从噪声里听出来；人声不发「喘」（pumping）。

**判定标准**：
- 通过：强载波时语音干净无削波；弱台可闻；开/关 AGC 对比明显但语音自然、包络不被压平。
- 不通过：强台仍过载失真；或弱台抬不起来；或音量随说话内容大幅起伏（明显 pumping）。

## 4. 渲染手感（doZoom 峰保持 + 瀑布历史重染）— 🟡 在途（P1）

**代码位置**：`src/ui/spectrum_render.h`（doZoom 块内取峰降采样、瀑布按新量程/色板重染历史行）；
交互侧 `src/ui/spectrum_display.cpp`。

**机制**：①频谱降采样取块内 max，缩小视图时窄峰不漏；②切色板/拖 dB 量程时，历史瀑布行按新映射重算而非清空。

**前置**：需 P1 合并、重新构建后做。

**验证方法**：
1. 在拥挤频段（如 FM 广播带 88–108 MHz）用 `Ctrl+滚轮` 反复缩小/放大视图。
2. 放大到某窄载波上，再缩小——观察该窄峰是否还在。
3. 瀑布运行几秒积累历史后，切换「经典/单色/Viridis」色板、拖动 dB 上下限。

**预期输出**：缩小视图不丢窄峰；切色板/量程时**已有瀑布历史行跟着重新上色**，而不是整块清空重来。

**判定标准**：
- 通过：一个窄载波缩小后仍可见（不被平均掉）；改色板后历史瀑布行即时换色，不黑屏重画。
- 不通过：缩小后窄峰消失（被取平均平滑没了）；或切色板瞬间历史全丢、只剩新数据。

## 5. 有理重采样音高（channelizer 有理分支）— ✅ 已落地（offscreen 单测覆盖渐近样点数）

**代码位置**：`src/dsp/rational_resampler.h`（多相窗 sinc，L 上采→抗混叠→M 下采，
滤波器历史与 commutator 相位跨块保持）；调用方 `src/dsp/channelizer.cpp`。

**机制**：out/in = L/M（GCD 约简后），流式跨块保持相位，渐近输出严格 = 输入×L/M，**无音高漂移**。

**验证方法**：
1. 接收 FM 立体声音乐或一个 CW/SSB 单音，连续听 2 分钟以上。
2. 对比有理分支开启前后（若有开关）或对比不经过重采样的直接采样率路径。

**预期输出**：长时收听下音高稳定，不出现缓慢地越飘越高/越低（chipmunk/慢放漂移），也无周期性抖动（warble）。

**判定标准**：
- 通过：连续 2 分钟音乐/单音音高恒定，无漂移、无周期性抖动。
- 不通过：听几分钟后人声/音乐明显变调或周期性起伏。

## 6. JSON 色板加载与诚实回退 — 🟡 在途（P1）

**代码位置**：`src/ui/spectrum_render.h:171` `parseColormapJson`
（形状 `{"stops":[[pos,"#rrggbb"], ...]}`，干净室，仅学 SDR++ colormaps.cpp 形状）。

**机制**：外部 `.json` 自定义 colormap；解析失败/格式不对时**诚实回退内置默认三档**，不崩。

**前置**：需 P1 合并、重新构建后做。

**验证方法**：
1. 准备一个合法色板 JSON（`{"stops":[[0.0,"#000000"],[0.5,"#0000ff"],[1.0,"#ff0000"]]}`），按 P1 落地文档指定的路径加载。
2. 再放一个**故意写坏**的 JSON（缺 `stops`、颜色写错、括号不闭合）。

**预期输出**：合法文件→瀑布换成自定义配色；坏文件→回退内置默认色板，日志记录回退原因，程序不崩。

**判定标准**：
- 通过：合法 JSON 立刻生效；坏 JSON 时退回默认色板且界面正常、日志说明「色板解析失败，回退默认」。
- 不通过：坏 JSON 导致崩溃、瀑布空白，或色板完全不生效。
