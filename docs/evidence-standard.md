# 真机证据判据（Evidence Standard）

> 适用对象：`docs/**/*.md` 与 `experiments/**/README.md` 里所有**带数字的结论**。
> 一句话：**没有原始件的结论不许留在正文里当事实用；不能复跑的，必须写时点与原因。**
>
> 工具：`scripts/audit_evidence.py`（本判据的可执行版本）。文档是规范，脚本是闸门。

## 1. 四级定义

| 级别 | 名称 | 定义 | 必须提供什么 | 能否当“当前事实”引用 |
| --- | --- | --- | --- | --- |
| **E1** | 有原始件（measured-archive） | 结论可由**入库的原始测量件**离线复算 | ① 原始件路径（`.json/.csv/.rgb/.sigmf-data/.log/.bmp/.wav/.bin` 等，非 `.md`）；② 采集条件（设备型号、固件/驱动、端口、日期）；③ SHA256 钉扎（或等价的内容哈希）；④ 复算脚本/命令与容差 | 能，且必须同时给路径与采集条件 |
| **E2** | 可复跑（rerunnable） | 无原始件，但仓内有**确定性命令/测试**能当场重算出同一数字 | ① 精确命令（`python …` / `pytest …` / `ctest …`）；② 期望值与容差；③ 最近一次通过记录（CI 或本地输出） | 能，但须注明“由命令复跑得出，非存档” |
| **E3** | 不可复跑（non-rerunnable） | 当时有证据，但原始件未入库或硬件/网络已不在 | ① 时点（`YYYY-MM-DD`）；② 证据形态（截图/日志片段/会话记录/commit）；③ **当前不可复跑的具体原因**（无硬件、无过境、外部服务变更等）；④ 要恢复可复跑还缺什么 | **不能**当“当前事实”引用；只能作历史线索，引用时带“当时有证据、现不可复跑” |
| **E4** | 未验证（unverified） | 没有任何可核对证据，或证据与结论矛盾 | ① 显式 `未验证` 标记；② 原因码；③ 需要什么数据/设备才能定 | **不能**；不得写成“已验证/实测通过” |

### 原因码（写进标记里，便于脚本与人工同口径）

| 码 | 含义 |
| --- | --- |
| `no-artifact` | 只有文档自述，无原始件 |
| `synthetic-only` | 只有合成 fixture/假后端自测，不构成外部验证 |
| `hardware-absent` | 本轮无设备（VNA/SDR/rotator/声卡） |
| `network-absent` | 需要外网/授权，本轮不可达 |
| `time-point-only` | 只有历史时点产物（如 `.tmp-tool-results`），当前不可复跑 |
| `contradicted` | 存档数据与结论直接矛盾（不是“没测”，是“测了不支持”） |
| `partial` | 结论的一部分有证据、另一部分没有（须逐项标明） |

## 2. 硬规则

1. **正文里的每个测量数字都要能落到 E1–E4 之一。** 落不到就是 `E4/no-artifact`。
2. **E4 不得写成事实。** 禁止“已验证/实测通过/真机验证”等字样；改为“未验证（原因码）+ 复跑条件”。
3. **E3 不得冒充 E1/E2。** 历史 `results.json`、旧聊天记录、截图缩略图只能作历史线索；必须写清时点与当前不可复跑原因。
4. **E1 的原始件不得被后续覆盖。** 替换采集件必须同步更新 SHA256 与采集记录；测试里用 SHA256 钉扎。
5. **合成信号永远不是外部证据。** 用仓库自己的编码器造 IQ、用假后端跑链路，一律 `synthetic-only`，不得标 `measured-archive`。
6. **一个证据不能给一串数字背书。** 同一段落的多个数字要逐个核对；只给其中一个找到原始件，其余降级。
7. **文档互相引用不算证据。** “见某某文档”最多是线索；两个文档写同一句话仍可能是同一次未留证的传闻。
8. **宁可降级，不要删除。** 保留结论与降级理由，方便以后拿到数据再升级。
9. **证据原件的扩展名必须落在可入库白名单内，提交后要 `git ls-files` 确认原件真的在版本里。**
   证据件先过 `.gitignore`：`docs/evidence/**` 由 `.gitignore` 的 `!docs/evidence/**`
   显式放行（该行必须排在 `*.log` 之后）；该目录之外一律按 `*.log` 等规则拦。
   新增扩展名前先 `git check-ignore -v --no-index <路径>` 验证，被拦就换扩展名或补规则。
   **只看 `git add` 没报错不算数**——`2026-11-06` 一份采样率读回原件因 `*.log` 被静默
   跳过，出现“台账已提交、原件不在版本里”，最后改名 `.txt` 补交（原件 `c438904c` —
   `docs/evidence/sample-rate-readback-20261106-0305.txt:2` — `RTL-SDR 真机`）。提交后必须
   `git ls-files docs/evidence` 复核，原件不在列表里就是不合规。

## 3. 反例（出现即判不合规）

| 反例 | 为什么错 | 正确写法 |
| --- | --- | --- |
| “真机实测 RMS=0.49”但仓内无 PSD/IQ/日志 | 无原始件，且可能与其他文档循环引用 | “未验证（no-artifact）：仅文档自述；复跑需 435.274MHz FM 录制 + `exp_ota_run.py`” |
| 拿 `.tmp-tool-results/20261103_*/results.json` 当“当前可复跑” | 历史产物、设备已拔、路径未入库 | “E3 时点 2026-11-03；当前 `device_count=0` 不可复跑；原始件未入库” |
| 合成 fixture 跑绿后写“真机验证通过” | synthetic-only 冒充外部验证 | “仅自测（synthetic-only），不构成真机证据” |
| 存档扫频显示 400–455MHz 单调下降，文档仍写“419.5MHz 谐振” | 有原始件且结论矛盾 | “E4/contradicted：存档不支持；最小回损在 400MHz 端” |
| 只给 commit hash 就声称“已验证” | commit 只证明改过代码，不证明测过硬件 | commit 只能支撑 E2（可复跑代码）或作为 E3 的时点线索 |
| “约 0.5s 传完”只有文档自述 | 无计时日志 | “未验证（no-artifact）；帧体积 153600B 有 E1 存档，耗时不详” |
| 证据原件用 `.log`（或任何被 `.gitignore` 拦掉的扩展名），提交成功但原件不在版本里 | `git add` 静默跳过被忽略文件，台账有、原件无，等于没证据 | 换成白名单扩展名（`.txt`/`.json` 等）或确认落在 `!docs/evidence/**` 放行范围内；提交后 `git ls-files docs/evidence` 复核 |

## 4. 工具口径（`scripts/audit_evidence.py`）

扫描对象：`docs/**/*.md` 与 `experiments/**/README.md` 的正文（跳过围栏代码块）。

对每个数字（带单位的数值或小数），看**附近窗口**（同一段 ±2 行）有没有：

- **commit**：7–40 位十六进制且能在 `git rev-parse` 里解析为 commit；
- **原始文件路径**：形如 `xxx/yyy.ext`，在仓内存在且不是 `.md`；
- **脚本命令**：`python` / `pytest` / `ctest` / `make` / `scripts/…`；
- **`未验证` 标记**。

输出三栏：

| 栏 | 含义 |
| --- | --- |
| 有证据 | 命中 commit / 原始文件 / 可复跑命令；括号内注明 `E1 有原始件` / `E2 可复跑` / `E3 不可复跑` |
| 无证据 | 什么都没命中，也没标未验证 |
| 已显式标未验证 | 窗口内有 `未验证`/`证据不足`/`待核实` 等标记 |

退出码：**存在任意一条“无证据且未标未验证”即返回 1**；全部有证据或已标未验证返回 0。
可用 `python scripts/audit_evidence.py --paths <file>` 对单个文件做反证；`--json` 输出机器可读结果。

强规则：正文里带 **`实测` / `测得` / `约` / `≈`** 的数字一律入账，必须有原始件路径、
可复跑命令或就地 `未验证` 标记，否则报红。

表格标注口径：`未验证` 只写在表头或同表别行时，**不给整表背书**。本行若真带原始件按 E1 计；
否则仍记“已标未验证”，但说明栏写明“仅同表他行标未验证（本行无标注，需核）”。

## 5. 与既有登记的关系

- `docs/limitations-register.md` 是**结论级**总账（能力有没有验过）；
- 本判据是**数字级**闸门（这句话里的数字有没有证据）；
- 两者冲突时以原始件为准，并把总账与本判据一起改。

## 6. 无证据数字的分类处置（`--classify`）

`python scripts/audit_evidence.py --classify` 在三栏之外，把“无证据”行按处置方式分五类
（分类**不放行**，退出码仍按三栏算；`--classify-samples N` 控制每类样本数）。

判定顺序（每条只进一个桶，可解释、可复跑）：

| 类 | 判定规则 | 处置 |
| --- | --- | --- |
| ① 无需证据 | 行内无测量动词，且命中参数/规格/判据、标准或外部引用、可推导常量（窗增益、fs/N、λ/4 等）；表头与 `|---|` 行不入账 | 保持原样，不补件 |
| ② 降级未验证 | 兜底：测量断言但无工件/无路径/无命令 | 就地标 `未验证（no-artifact）` 或改写为“仅自测/待测” |
| ③ 有工件缺路径 | 行内点名的数据文件/`exp_*.py` 在仓内存在，或 `experiments/*/README.md` 同目录有 `data/` 采集件 | 补显式相对路径或测试命令，升 E1/E2 |
| ④ 必须补测 | `hw-acceptance` / `real_hw_acceptance_*` / `dsp-performance-baseline` 里的 PASS、总耗时、吞吐等载荷性数字 | 重跑验收/基准，留原始件；标“未验证”不够 |
| ⑤ 删除改写 | 带删除线 `~~`、显式撤回/作废、把预期值写成实测 | 删除或改写为预期/未验证表述 |

### 7.7 四元组行号的坐标口径（2026-11-06 写死）

**口径**：`path:N` 是**当前 HEAD 坐标**。新增的「行号内容校验」必须取
`git show HEAD:<path>` 的第 N 行，判断该行是否包含被引字面量；**不得取被引提交坐标**
（`git show <hash>:<path>` 第 N 行）来判。

**依据（8/8 反例，2026-11-06 实测）**：settings-inventory 那批 8 条四元组在 HEAD 坐标
全部成立，但在被引提交坐标全部不成立：

- `2614c7f8` 的 `desktop/config_schema.py:377` 当时是 `agc_enabled`
  （不是 `pass_min_elevation_deg`）；
- `6ed9ee7d` 的 `mbdsdr_ai/sdr_backend.py:111` 当时是空行
  （不是 `DEFAULT_SAMPLE_RATE_HZ = 2_400_000`）。

同一批四元组在两套坐标下会被判成相反结果，所以口径必须在校验实现前钉死。

**区间行号**：`path:N–M` 默认只取首行 N 判定；确需「区间内任一」语义时，必须在字面量后
显式写 `区间内任一`，否则按首行判。

**与现有三步的关系**：`verify_claims` 现三步只校验「该提交确实改过该路径、且
`git log -S` 能在同一 hash 命中该字面量」（`cat-file` / `--name-only` / `log -S`），
**不校验行号内容**；第 4 步（HEAD 第 N 行含字面量）就是补这一环，判红名为「行号失效」。

### 7.8 统计快照的生成方式（2026-11-06 写死）

**规则**：凡对外引用的「断言分布 / 文档统计」快照，必须用 `git archive <HEAD> <dir>` 生成，**禁止**用 `git ls-tree --name-only` 的文本输出自行拼装。违反时数字会静默偏小，且无法复现。

**实证一（少 16 条）**：`core.quotepath=true` 下 `git ls-tree -r --name-only HEAD docs` 把 `docs/PRD-现状对照.md` 输出为 `"docs/PRD-\347..."`（带引号的八进制转义）。按「以 `.md` 结尾且不含子目录」过滤时该行被静默跳过 → 顶层断言数 156 变成 140，差额正好是 `PRD-现状对照.md` 的 16 条（`e4810574` 实测）。

**实证二（多算 / 不可追）**：复用旧临时快照目录（未清空就再抽下一个 HEAD）会把上一轮文档残留带进来，产生重复计行。`b0a440e3` 曾被报成 164（同口径正确值 156），该临时目录已无工件可追，只能作废。

**复现式（唯一口径）**：

```text
git archive <HEAD> docs | tar -x -C <tmp>
git show <HEAD>:scripts/verify_claims.py > <tmp>/vc.py
python <tmp>/vc.py --root <repo> --docs <tmp>/docs
```

- 范围：`docs/*.md` 顶层、非递归（加 `--recursive` 是 412，不是同一口径）；
- `EXCLUDE_FILES={claim-waivers.md}`；`audit_r2` 是子目录，顶层本就不含；
- `CLAIM_RE` 与该 HEAD 提交版逐字一致；豁免条数不参与统计（校验器只整文件跳过 `claim-waivers.md`）；
- 校验器必须是**该 HEAD 的提交版**（`git show <HEAD>:scripts/verify_claims.py`），不得用工作区在途版。

**已核对的分布**（同口径重跑，引用时带哈希）：`b0a440e3` 156/58/12/86；`d731bdeb` 156/58/12/86；`e4810574` 156/63/12/81；`81cd345a` 156/63/13/80。旧值 `164/58/17/89`、`140/58/12/70` **作废**。
