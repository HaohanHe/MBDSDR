- 审计日期：2026-11-05
- 审计视角：第一次使用本软件、没有硬件、没有配置的新用户
- 代码现场：`D:\mbdsdr\MBDSDR`，工作树多线并行（`desktop/main_window.py`、`desktop/rf_sky_view.py`、`desktop/settings.py` 等有他线在途改动）
- 取证方式：离屏渲染真实 `MainWindow`（`QT_QPA_PLATFORM=offscreen`），隔离 `HOME/APPDATA`，不接真实 SDR；截图在 `docs/ux-audit-assets/`，探针脚本在仓库外 `D:\mbdsdr\ux_probe.py`
- 已知在途阻塞：审计开始时 `desktop/config_schema.py`（他线新文件）缺 `help=` 导致应用无法 import；审计过程中该文件被他线补全，未计入本清单

## 严重度定义

| 级别 | 含义 |
|---|---|
| P0 | 应用起不来 / 数据丢失 / 无法完成任务 |
| P1 | 让人以为成功其实没做；或让人以为软件坏了；或误操作不可挽回 |
| P2 | 明显困惑、要多试几次、反馈缺失 |
| P3 | 不顺畅、不美观、边界情况 |

## 总览

**共 18 条：P1 8 条，P2 8 条，P3 2 条。**

最该先修的 3 条：

1. **UX-01 点卫星没设备也报「已自动调谐」**（`main_window.py:7460-7502`）。这是最严重的“假成功”：天空页点一下 ISS，状态栏就说已跟踪并自动调谐，频率标签改到 145.8 MHz，而实际上没有 SDR、没有任何调谐。违反“诚实优先”铁律，且发生在主场景 4。
2. **UX-02 硬件调谐/增益/解调失败被静默吞掉，界面和配置照常更新**（`main_window.py:3899-3962`、`3986-4003`、`4073-4118`）。主场景 3 的每一次调谐都可能“显示成功、实际没动”，并且失败值被写进配置，下次启动继续骗人。
3. **UX-03 AI 工具失败不汇总，模型文字可以一直宣称成功**（`ai_panel.py:769-826`、截图 `07-ai-tool-failure.png`）。用户只看到“已为你调谐到 145.800 MHz”，步骤卡里虽有一个小 FAIL，但对话结论没有被纠正；这是场景 5“模型自己以为成功了怎么暴露”的核心缺口。

### 确认框默认按钮口径（2026-11-14 定，落地时逐处对齐）

规则（写死在文档，改 UI 时按这条走，不再各写各的）：

1. **破坏性 / 不可逆操作**（删除、清空、覆盖、断开正在进行的采集）必须二次确认，且 `QMessageBox.question(..., Yes|No, QMessageBox.No)` **默认按钮必须是 No**——回车不能等于执行破坏。
2. 正文必须写清三件事：做什么、后果、能不能撤销/是否落盘到哪。
3. **可逆操作**（调谐、切换显示、打开面板）可以默认 Yes，也可以不弹；不要把可逆动作做成拦路确认。
4. 判据：打桩 `QMessageBox.question` 后断言第 4 个实参就是 `QMessageBox.No`；反证是把默认按钮去掉后该用例必须红（Qt 默认选中第一个按钮 = Yes）。

现有五处破坏性确认（均为默认 No，作为对照基线）：
