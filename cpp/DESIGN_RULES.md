# MBDSDR 前端设计宪法（新原生 C++ 前端必须遵守）

本文件是新前端动手前的硬约束。**写任何代码前先读本文件。** 目的：一次写对，不返工。

## 1. 架构：UI 与引擎同体，禁止两层皮
- 单一进程。DSP/射频引擎线程产出的数据，**直接**喂给同进程 UI 视图；不允许"先摆个假面板、以后再接数据"。
- 一份数据模型。频谱、解调、设备状态只有一个真相源；UI 是它的投影，不自己造数。
- 测试信号可以有，但必须**明确标注**是测试源，绝不冒充真实硬件读数。无硬件时显示空态"未连接"。

## 2. 设计语言（对齐 Figma 平行视界）
- 底色：`#000000` / `#080a0c`；卡片 `#1f1f1f` / `#2b2c2f`；分隔线 `rgba(255,255,255,.08)`。
- 文字：主 `#ffffff`；次级 `#939393`；弱化 `#6b727c`；更弱 `#4f5359`。
- 点缀冷蓝灰 `#919cac`；成功 `#5fd08a`；警示 `#e0b35a`。
- 圆角：卡片 13px；胶囊按钮 42/84px；圆形 50%。
- 字阶：大数字 42/39/48px；次级 20/24px；正文 13-14px；辅助 11-12px。
- 毛玻璃：背景模糊 20px 量级 + 低透明黑阴影。
- 字体：MiSans / Inter / PingFang SC / 系统默认无衬线。
- 布局：固定三栏平行视界（左天空轨道 / 中地图世界铺满可全屏 / 右当前任务），QSplitter 可拖宽，比例与面板显隐持久化。底部 Home + 模式块 + Now Bar。
- 不要自由满屏浮窗；是停靠式弹性。

## 3. 禁止隐式硬编码（本文件的核心）
- **颜色、尺寸、圆角、间距、字号、频率默认值、阈值**——一律集中到一个 `Theme` / `tokens.h` 常量文件，业务代码只引用命名常量，不写裸 `#hex`、不写裸像素数。
- 允许局部"隐式硬编码"的**唯一例外**：与具体算法/物理量绑定、且改动会改变行为的数值（如滤波器抽头数、FFT 点数、解调带宽的物理参数）。这种必须就近加注释写明依据（参考了哪个开源实现/数据手册）。
- UI 外观值（颜色、大小、间距、圆角）**不允许**散落在业务代码里。
- 不预存任何 FM 台频点；不写死地理位置。

## 4. 交互与可触性
- 触屏与鼠标同等一等公民：可点目标 ≥ 44×44 逻辑像素；不依赖 hover 才出关键反馈。
- 频谱/天空/地图：单指拖、双指捏合缩放；splitter 拖拽热区够宽。
- 面板可停靠/折叠/临时收起；布局用户可保存、命名、恢复出厂。

## 5. 工程规范
- CMake + Qt6 Widgets；目标 release 出单可执行文件。
- 命名一致、模块边界清晰；新增解码器/工具=注册一处，不改核心。
- 不出现任何比赛相关字样；不提交设计稿素材；不内置任何密钥。
- 每个新模块配可离线跑的测试（Qt offscreen）。

## 6. 验收口径
- 改主题/配色：只动 tokens，全 UI 跟着变。
- 加一个数字模式：写解码类 + 注册一行，UI 自动出现。
- 起窗后不接硬件：处处空态，没有一个假数字。
