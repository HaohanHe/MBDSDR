# 04 · 国际化（i18n）规范

## 1. 单一文案来源

所有用户可见文字只在 `src/20-i18n.js` 的 `D` 词典里出现一次，结构：

```js
"key.name": { zh: "简体中文", ja: "日本語", en: "English" }
```

- `zh` 是**反查主键**：静态 HTML 里的中文原文经 `norm()`（压缩空白 + trim）后查 `LOOKUP`，命中即替换。
- 动态内容（信息卡、能力矩阵、对话、状态栏、工具卡）一律 `MB.i18n.t(key, vars)`，模板用 `{name}` / `{band}` / `{n}` 占位。
- 语言切换时每个文本节点的原文缓存在 `node._i18nSrc`，属性缓存在 `el._i18n_<attr>`，可反复切换、不累积翻译。

## 2. 三种语言

| 代码 | 名称 | 用途 |
|---|---|---|
| `zh-CN` | 中文 | 默认；静态 HTML 原文语言；文档原文 |
| `ja-JP` | 日本語 | 界面 + 对话模板全量 |
| `en-US` | English | 界面 + 对话模板全量 |

术语统一口径（详见 [wiki/glossary.md](wiki/glossary.md)）：

| zh | ja | en |
|---|---|---|
| 星象仪模式 | プラネタリウムモード | Planetarium Mode |
| 专业模式 | プロフェッショナルモード | Professional Mode |
| 能力，而非流程 | 機能ではなく能力 | Capability, not workflow |
| 摄像机锁定 · 天动星静 | カメラ固定 · 天が動き衛星は静止 | Camera lock · sky moves, satellite stays |
| 追踪 / 接收 / 指向 | 追跡 / 受信 / 指向 | Track / Receive / Point |
| 能力矩阵 | 能力マトリクス | Capability Matrix |
| 模型现场能力协商 | モデルによるその場の能力確認 | On-the-spot capability negotiation |
| 定轨（仅对话） | 軌道決定（対話のみ） | Orbit determination (dialog only) |

## 3. 静态 / 动态分工

| 区域 | 处理方式 | 标记 |
|---|---|---|
| 顶栏、侧栏、按钮、占位符、工具栏 title | `applyStatic()` 扫描替换 | — |
| 信息卡、能力矩阵、AI 流、专业模式协作栏、状态栏、文档中心 | JS 用 `t()` 重新生成 | `data-i18n-skip` |
| 文档正文 | 文档中心按 `docLocale` 单独渲染 | `#docBody` 跳过 |

**规则**：凡是 JS 会重写的容器，必须打 `data-i18n-skip`，否则静态扫描会把动态生成的中文字串记成"缺失词条"，并在下次切换时误替换。

## 4. 定轨的国际化纪律

`定轨 / 軌道決定 / orbit determination / orbit` 的识别只在 `i18n.isOrbitRequest(用户输入的文本)` 里；对应模板 `dialog.orbit` 也只在对话流中使用。校验脚本会扫描功能面（按钮 `data-act`、`CAPS`、`TOOLS`、信息卡读数、工具卡），**发现即失败**。

## 5. 校验

`tests/verify_product.py` 会检查：

1. 每个词条三语齐全且非空；
2. `t("…")` 与 `data-i18n` 引用的 key 都存在；
3. 静态 HTML 中的中文文本/属性全部能被 `LOOKUP` 命中（跳过 `data-i18n-skip` 容器）；
4. JS 里没有硬编码中文（注释、日志、字符串允许规则见脚本白名单）；
5. UI 功能面无定轨入口。

新增语言流程：

1. 在 `D` 的每个条目加新字段（如 `ko`）；
2. 在 `LOCALES`、`FIELD`、`label()`、`docs` 语言降级里登记；
3. 补 `docs/README.<lang>.md` 等译本（缺译时文档中心会如实标注）；
4. 跑校验与构建。

## 6. 已知取舍

- 数字、单位、呼号、卫星编号、工具名保持原文（跨语言稳定，便于与日志/金样对照）。
- 文档主语言为中文；目前提供英文/日文 README 作为译本演示，其余文档缺译时明确标注，不假装已本地化。
- 不做 RTL 布局（三种语言均 LTR）。


## 事实数据的本地化边界（0.3.0）

域名、工具名、卫星名、端口号属于**仓库事实**，不做翻译、不写死在 JS 里，
统一由 `build/repo-facts.json` 提供。产品的本地化层只负责：域名的日/英译名、
图标、稳定 id（`sync_from_repo.py` 的 `DOMAIN_I18N`）与全部 UI 文案词条。
新增词条后必须三语齐全，`tests/verify_product.py` 会核对静态文案反查与代码引用。
