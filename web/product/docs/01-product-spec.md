# 01 · 产品规格与铁律

> 本文是 UI / 产品决策的最高依据。任何新功能先对照铁律，再谈实现。

## 1. 一套系统，两副面孔

不是两个软件，是**同一套能力核心的两种视图**，类比 IDE / Agent 双形态：

- **专业模式**：传统 SDR 工具化（频率、增益、带宽、参考电平、解调链 + 频谱瀑布 + 协议栈树），右侧常驻模型协作栏。内核本来就是 SDR，这里只是把它工具化。
- **星象仪模式**：打开瞬间整个天空"唰"地展开；点选卫星后信息铺开。参考形态是 Stellarium Web，参考机制是 Stellarium Web Engine（见 [06-compliance.md](06-compliance.md)）。

两形态共用 `state`、`caps`、`DataSource` 与协商引擎；切换形态只换视图，不换能力。

**两个主导（用户口述铁律）**：星象仪模式以**时空**为主导（全天球、坐标、时刻、LST、FOV、极限星等）；专业模式以 **SDR·频谱**为主导（调谐、解调、工具树、协作栏）。两者不是同一张皮换色，而是两套不同的信息主次。

## 2. 摄像机语义（铁律）

**锁定卫星后镜头跟星走：天在动、星不动。**

- 卫星钉在画面中心，背景天球随时间与视角运动；不是"卫星在天上飞过去，镜头不动"。
- 星空（ICRF）随时间转；地景固定在 OBSERVED 地平坐标系，**不随时间转**，只随用户拖拽/缩放动。这就是"地景是动的"的正确含义：跟着相机走，不跟着时间走。
- 拖拽 = grab-the-sky：按下点反投影成世界方向，全程钉在光标下；滚轮 = 改 FOV，并做 zoom-to-cursor 反补。
- 选中标记是 2D 层逐帧重投影，带 2 秒呼吸的虚线追踪环。
- 解除锁定**不把视角弹回中心**，原地脱离。

## 3. 能力，而非流程（铁律第一原则）

- 能力矩阵由**原仓库真实工具域**生成（冻结域 + Python 扩展域，工具名来自 `_TOOL_DOMAIN`）；
  6DOF 视觉引导 / 视觉校准 / VR·XR 属于**规划 · 未验证**，单列一组、开关禁用。
  全部是**模型可调用的能力位**，可开关、可持久化、可组合；空域保持诚实空态。
- **绝不预制向导、步骤条、死流程**。点「追踪」「接收」「指向」只是把对话打开，**模型现场问你**：有 SDR 吗？什么型号、覆盖到哪个频段？有云台吗？有 GNSS 吗？答案不同，装配出来的任务就不同（例如 PlutoSDR 在 137 MHz 需上变频器；无 SDR 降级为过境预报 + 记录计划）。
- 能力矩阵是能力位清单，不是执行顺序；顺序由模型根据现场条件动态组织。
- 布局弹性可动：专业模式三分栏可拖分隔条，抽屉可折叠，面板动态。

## 4. 定轨不是功能（铁律）

**UI 上不得出现任何定轨按钮、能力位、工具入口、信息卡读数或推销话术。**

- 唯一触发方式：**用户开口跟模型说**（AI 抽屉底部对话输入，或专业模式协作栏）。
- 对话流里的工具调用不算功能面；模型只在被要求时才组织多普勒观测 → RLS 估计这条能力链。
- 天体轨道弧、轨道线显示开关是**几何数据结构**，不是定轨功能，保留。
- 自动校验：`tests/verify_product.py` 扫描 `data-act`、`MB.CAPS`、`MB.TOOLS`、按钮文案与工具卡，发现定轨即失败。豁免区仅 `20-i18n.js` 的对话模板与 `isOrbitRequest()` 关键词。

## 5. 信息铺开

点选卫星后信息卡展开：NORAD 编号、别名（可点）、星等/距离/RA-Dec/Az-Alt/可见窗口/下行频率/体制/多普勒、描述、**真实 Wikipedia 外链**、摄像机锁定状态、三个动作按钮。字段值逐字与卫星目录一致；站址未校准时明确标注不可用项。

## 6. 场景覆盖

同一套能力要撑住三类场景，不各做一套软件：

| 场景 | 典型组合 | 说明 |
|---|---|---|
| 科教教培 | SDR + 频谱 + 协议栈 | 天球周日视运动时间倍率演示、灰阶瀑布、真录解码金样 |
| 科学研究 | + GNSS + 6DOF | 可追溯数据链、金样对拍、误差留痕、not_verified 诚实标注 |
| 通联 / 应急 | + 云台 + 指向 | 过境窗口、指向闭环、无设备时的降级方案 |

## 7. 诚实边界

- 演示数据必须标注为演示数据；无 TLE 不说有轨道解，站址不可信不说能预报过境。
- 内核未连接时，工具调用返回**离线失败回执**，不伪装成功、不吞异常。
- 每个能力词条写清 `not_verified`：哪些没验证、验收口径是什么。

## 8. 非目标（本版本明确不做）

- 实时 TLE 拉取与 SGP4 传播（留给内核桥）。
- 真实 IQ 采集与解调（留给 `mbdsdr_ai` 内核）。
- 用户账号、云同步、遥测上报。
- 任何把能力写死成流程的"新手引导"。


## 事实源与诚实边界（0.3.0 追加）

- 能力位、工具名、卫星目录、通道端口、时间倍率、设计令牌**由 `build/sync_from_repo.py` 只读抽取原仓库代码**，
  不手抄设计稿；`docs/mcp_tools.md` 的自动生成标记区与 README 的域数均已漂移，不作为依据。
- 无硬件 → 显式空态 / `not_connected` 信封，**绝不合成 IQ 或伪造频谱**；
  `debug` 类调试源若存在必须显式标「非真实设备」。
- 写工具确认门由宿主 / 外部确认通道持有（事实源 `MB.REPO.gates`）：ControlHub 是 C++ 宿主写开关 `writeEnabled_`，Python 内核是外部签发的一次性 `confirm_token`。**模型自报 `arm_manual` 无效**；`gated:true` = 未获确认，不是执行失败；前端只透传，不签发 token、不自判放行。
- 不硬编码能力数字（工具数 / 测试数 / 域数），能力用可复跑命令证明。
- 默认站点为中性示例 `0.0, 0.0`、`trusted=false`；未校准时拒绝锁定与过境结论。
- 6DOF / AR / VR 等规划项带 `not_verified` 标注，不包装成已上线能力。
